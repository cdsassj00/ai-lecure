FRAME 0

전체 그림

LLM, 에이전트, 브릿지, 내 PC 자동화가 하나의 흐름으로 이어집니다. 이 구조는 단순 챗봇을 넘어 실제 업무 자동화로 가는 구조입니다.

FRAME 1

클라우드 LLM

LLM은 기본적으로 학습한 텍스트 패턴과 현재 대화 맥락을 바탕으로 답변합니다. 외부문서, 웹, 프로그램 정보는 직접 가지고 있는 것이 아니라 연결되어야 읽고 사용할 수 있습니다.

FRAME 2

에이전트의 역할

에이전트는 LLM이 스스로 “무엇을 확인해야 하는지, 어떤 도구를 써야 하는지, 다음 행동은 무엇인지”를 계획하도록 만든 실행 패턴입니다.

FRAME 3

LLM의 한계

클라우드 LLM은 내 PC의 운영체제, 로컬 파일, 파이썬 실행환경, 브라우저 내부 조작 권한을 기본적으로 갖고 있지 않습니다. 그래서 연결 계층이 필요합니다.

FRAME 4

브릿지와 하네스

브릿지/하네스는 클라우드의 판단을 로컬 실행환경으로 안전하게 전달하는 중간 계층입니다. 명령을 번역하고, 권한을 제한하고, 결과를 다시 LLM에게 돌려줍니다.

FRAME 5

내 PC 자동화

실제 실행은 내 PC에서 일어납니다. 운영체제 명령, 파이썬, 로컬 파일 접근, 엑셀·PDF·브라우저 자동화는 PC 쪽 실행환경이 담당합니다.

FRAME 6

코딩 에이전트

Codex, Claude Code, Antigravity, Cursor 같은 코딩 에이전트는 이 구조를 개발 업무에 특화한 형태입니다. 파일을 읽고, 코드를 수정하고, 명령을 실행하며 결과를 다시 해석합니다.

FRAME 7

결론

요약하면 LLM은 머리, 에이전트는 작업관리자, 브릿지는 연결장치, 내 PC는 손발입니다. 이 네 요소가 연결될 때 “답변 생성”이 “업무 수행”으로 바뀝니다.
