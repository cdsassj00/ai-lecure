UNIT 02 · 도구 투어 ① · LECTURE 06-B-1

Claude Code — 터미널 한 창에서 프로젝트 전체를 다루는 풀 에이전트

Anthropic 공식 CLI 에이전트. 파일 읽기·수정·실행·커밋·테스트 전 과정을 스스로 수행한다. 거점리더의 주력 도구.

01 · WHAT IT ISnpm 한 줄로 시작
터미널에서 대화하는 IDE-리스 에이전트

GUI 편집기 없이 터미널만 있으면 된다. 현재 폴더를 루트로 삼아 파일 구조를 읽고·탐색하고·편집하고·실행한다. 공공 내부망에서 별도 IDE 설치 허가가 까다로울 때 가장 장벽이 낮은 옵션.

# 설치 (외부망 1회) npm install -g @anthropic-ai/claude-code # 프로젝트 폴더에서 실행 cd ~/work/민원분류 claude # 대화창이 열리면 바로 지시 > 이 폴더의 민원.xlsx를 읽고, 부서별로 자동 분류한 결과 시트를 추가해줘.
WHEN TO USE
프로젝트 규모 · 터미널 친숙도 · 승인 환경

파이썬 프로젝트, 자동화 스크립트, 데이터 파이프라인 — CLI 친화 업무에 최적.

02 · CORE LOOPPlan → Edit → Test → Review
에이전트 루프 4단계
01
Plan · 계획 먼저 받기
/plan 명령 또는 "먼저 계획만 보여줘"로 실행 전 검수
02
Edit · 파일 직접 수정
diff를 보여주고 사용자 승인 후 적용. y/n로 컨트롤.
03
Run · 터미널 실행
pytest, python main.py 등을 에이전트가 직접 실행
04
Review · 에러 자가 수정
실패 시 트레이스백을 읽고 고쳐서 재시도
TYPICAL SESSION
1턴 지시 → 8턴 자가 루프 → 1턴 검수

사람이 10분 투자하면 에이전트가 30~90분치의 구현을 수행. 검수는 diff와 로그로.

주요 명령 단축
/plan — 실행 없이 계획만
/clear — 대화 초기화
/memory — 장기 메모리 편집

Cursor · Antigravity — 편집기 안으로 들어온 에이전트

VS Code 포크 기반의 에이전트 IDE. 시각적 diff·탭·파일 트리 — 익숙한 환경 위에서 에이전트를 호출한다.

01 · CURSORVS Code + 에이전트
"VS Code를 쓰던 사람이 그대로 옮겨오는" 진입 경로

기존 VS Code 확장·단축키·폰트 그대로. 우측 패널에 에이전트 채팅이 상주한다. Cmd/Ctrl+K로 선택 영역 리팩토링, Cmd/Ctrl+L로 채팅·에이전트 호출.

MODE범위용도
Ask현재 파일질의응답
Edit선택 영역인라인 수정
Agent프로젝트 전체멀티파일 작업
Bug에러 지점자동 디버깅
STRENGTH
diff를 한 블록씩 Accept/Reject

에이전트 변경을 파일 단위가 아닌 헝크 단위로 선별 수용. 검수 품질이 높다.

// .cursor/rules/style.md 예시 당신은 공공기관 실무 개발자입니다. 주석은 한국어로 작성하고, 파일명은 {날짜}_{용도}.py 규칙을 따릅니다. 민감 정보는 로그에 남기지 않습니다.
02 · ANTIGRAVITYGoogle의 에이전트 IDE
Windsurf의 계보를 잇는 Google 에이전트 IDE

Cursor와 유사한 VS Code 포크 구조지만, 에이전트 자율도 기본값이 높다. 한 지시에 여러 파일·여러 커맨드를 연쇄 실행하는 "Cascade" 흐름. 2025 공개

CASCADE
연쇄 실행 흐름

에이전트가 파일 스캔 → 수정 → 실행 → 수정을 한 번의 "연쇄"로 묶어 보여줌. 타임라인 형태로 기록.

TIMELINE
변경 이력 시각화

각 단계를 체크포인트로 저장. 특정 시점으로 되돌리기 가능.

MEMORIES
프로젝트별 자동 기억

파일 스타일·선호 패턴을 자동 학습해 다음 세션에 반영.

두 도구의 선택 기준

Cursor: 세밀한 통제와 기존 VS Code 자산 활용. Antigravity: 빠른 초안과 에이전트 자율성.

Codex · OpenCode — OpenAI 계열과 오픈소스 대안의 지도

도구 5종의 지형을 한 화면에 정리한다. 도구는 바뀌어도, 선택 기준은 그대로다.

01 · CODEXOpenAI 공식 에이전트
터미널·IDE·웹까지 지원하는 OpenAI의 풀라인

OpenAI가 제공하는 공식 에이전트 제품군. Codex CLI(터미널)와 Codex Cloud(웹)가 축을 이룬다. ChatGPT 구독이 있다면 별도 가입 없이 바로 접근 가능해 행정 허들이 낮다.

# Codex CLI 설치 npm install -g @openai/codex # 실행 — 프로젝트 루트에서 codex # 인수로 바로 지시 codex "민원.xlsx를 부서별로 분류해줘"

환경이 제한된 공공 PC에서도 최소 한 가지 경로는 열려 있다.

02 · OPENCODE오픈소스 에이전트
특정 벤더에 묶이지 않는 오픈소스 CLI 에이전트

OpenCode는 Claude·OpenAI·Gemini·로컬 모델(Ollama)까지 하나의 CLI에서 교체 가능하다. 보안 정책상 특정 벤더 사용이 제한될 때, 또는 로컬 모델로만 운용해야 할 때 유일한 선택이 된다.

# OpenCode 설치 npm install -g opencode-ai # 모델 교체 opencode --model claude-sonnet-4 opencode --model gpt-5 opencode --model ollama/llama3.2 # 로컬
외부망 · 클라우드 모델

Claude·GPT·Gemini API 키로 접근. 코드가 외부로 전송됨을 기관 정책과 대조.

내부망 · 로컬 모델

Ollama 연결 시 완전 오프라인 에이전트. 속도는 느리지만 민감 데이터 안전.

USE CASE

UNIT 03 · Rules · LECTURE 06-C-1

Rules — "매번 하는 말"을 파일 한 장으로 자산화한다

AGENTS.md · CLAUDE.md · .cursor/rules. 이름은 달라도 원리는 같다. 에이전트가 자동으로 읽는 프로젝트 헌법.

01 · WHY RULES반복 지시의 자산화
Rules는 "설명하지 않아도 당연한 전제"를 적는 곳

매 세션마다 "한국어로 답해줘", "파일명은 이 규칙", "민감 정보는 로그에 쓰지 마" 같은 지시를 반복하는 것은 에이전트 사용의 가장 큰 낭비다. Rules 파일은 에이전트가 세션 시작마다 자동으로 읽는 지시서다.

TOOLFILE
Claude CodeCLAUDE.md · AGENTS.md
CodexAGENTS.md
Cursor.cursor/rules/*.md
Antigravity.windsurfrules
OpenCodeAGENTS.md
KEY TAKEAWAY
AGENTS.md는 점차 업계 표준이 되고 있다

한 번 잘 쓰면 도구를 바꿔도 거의 그대로 사용 가능.

02 · STRUCTURERules 표준 섹션
공공 실무용 AGENTS.md 권장 5섹션
# AGENTS.md · 민원분류 프로젝트 ## 역할 & 톤 한국어로 답변. 존댓말 사용. 담당자 설명을 위한 주석은 쉬운 한국어로. ## 코드 스타일 - 파이썬 3.11 기준 - 파일명: {YYYYMMDD}_{용도}.py - 함수명 snake_case, 클래스 PascalCase - 외부 라이브러리는 requirements.txt에 기록 ## 보안 - 주민번호·이름·연락처는 로그 출력 금지 - API 키는 .env 사용, 코드에 하드코딩 금지 - 외부망 호출 코드는 별도 파일로 분리 ## 검증 - 모든 스크립트는 pytest로 샘플 5건 테스트 - 실행 전 /plan 필수 ## 금지 - rm -rf 계열 명령 - 원본 파일 덮어쓰기 (.bak 백업 후 수정)
03 · HANDS-ON · LAYER개인·부서·프로젝트 3층
Rules는 3계층으로 운영한다
01
전역 — 개인 공통
~/.claude/CLAUDE.md 에 항상 쓰는 톤·언어 설정
02
부서 — 공용
\\DEPT\AGENTS.md 에 부서 표준 (파일명·보고 양식)
03
프로젝트 — 세부
./AGENTS.md 에 특정 업무 규칙 (데이터 스키마 등)
에이전트는 3장을 모두 읽고 우선순위는 프로젝트 > 부서 > 전역
FIELD CASE · 부서 AGENTS.md
"보고서는 한글(.hwp)만, 표는 4열 이내"

부서 전원이 이 규칙으로 에이전트를 쓰므로 산출물 일관성이 담보된다.

PITFALL
▸ Rules를 너무 길게
200줄 넘기면 에이전트가 주요 규칙을 놓친다. 핵심만 60줄 이내.
▸ 상충 규칙 방치
부서와 프로젝트 규칙이 충돌하면 명시적으로 한쪽에 "예외" 표기.
개인 CLAUDE.md 1회 작성
프로젝트 AGENTS.md 템플릿 보유

UNIT 03 · Skills · Sub-agent · LECTURE 06-C-2

Skills는 "재사용 가능한 전문 모듈", Sub-agent는 "일을 나눠 주는 동료"

Rules가 한 장의 헌법이라면, Skills는 서랍장에 든 공구 세트. Sub-agent는 한 팀 안의 역할 분담이다.

01 · WHAT IS A SKILLRules와의 차이
Skills = "필요할 때만 꺼내 쓰는" 전문 매뉴얼 폴더

Rules는 항상 모든 세션에서 적용된다. Skills는 특정 작업 상황에서만 자동으로 활성화된다. 예: "HWP 작성해줘"라고 하면 hwp-작성 Skill이 자동 호출된다.

CRITERIONRULESSKILLS
범위전역 상시상황별
형식마크다운 1장폴더+SKILL.md
호출자동키워드 매칭
파일규칙만예시·템플릿 포함
# Skill 디렉토리 예시 ~/.claude/skills/ hwp-공문/ SKILL.md # 설명+트리거 키워드 template.hwp # 양식 샘플 fields.md # 누름틀 목록 민원-분류/ SKILL.md 라벨정의.md 예시50건.csv
KEY TAKEAWAY
Skill은 팀이 공유하는 "전문 매뉴얼"

한 명이 만들고, 부서 전원이 에이전트로 호출해 쓴다.

02 · SKILL.md최소 구성 요소
Skill 폴더 안 SKILL.md — 3가지만 적으면 된다
# SKILL.md · hwp-공문 --- name: hwp-공문 description: 기관 표준 공문 HWP 양식으로 문서를 생성할 때 사용한다. "공문 써줘", "기안문 만들어줘" 같은 요청에 활성화. --- ## 사용 방법 1. template.hwp를 복사 2. pyhwpx로 아래 필드를 채운다: - 문서번호, 제목, 수신자, 본문 3. 파일명: {YYYYMMDD}_{제목10자}.hwp ## 참고 파일 - fields.md — 누름틀 전체 목록 - example.py — 작성 샘플 코드

frontmatter의 description이 가장 중요하다. 에이전트는 이 설명을 읽고 "지금 이 Skill을 써야 하는가"를 판단한다. "언제 쓰는가"를 명확히 적을수록 자동 활성화 정확도가 올라간다.

PITFALL
▸ description이 모호하다
"HWP 관련 작업"이라고만 쓰면 엉뚱한 상황에도 호출된다. 구체적인 트리거 문구 예시를 넣는다.
03 · SUB-AGENT역할 분담·병렬 실행
Sub-agent = "특정 역할만 맡는" 부하 에이전트

복잡한 과제를 한 에이전트가 모두 처리하면 맥락이 오염된다. Sub-agent는 "데이터 정제 담당", "보고서 작성 담당"처럼 역할을 쪼개 병렬·직렬로 협업한다.

MODULE 06 · UNIT 04 · SPEAK ARCHITECTURE · HOW TO INSTRUCT
공공 AI 전문인재 양성과정 · 8주 실전 여정
UNIT 04 · 아키텍처로 말하기 · LECTURE 06-D-1

아키텍처로 말한다 — 에이전트에게 주는 입력은 "설계서"다

한 문장 프롬프트가 아니라, 4섹션의 설계서. 에이전트는 문장력보다 구조를 잘 받아낸다.

01 · FOUR SECTIONS입력·처리·출력·검수
에이전트 지시서의 표준 4섹션

어떤 과제든 입력(무엇을 주는가) · 처리(어떻게 변환) · 출력(무엇을 남기는가) · 검수(어떻게 확인) 네 칸으로 쪼갠다. 이 구조가 숙달되면 한 장 설계서가 15분 안에 완성된다.

① INPUT
입력 명세

파일 경로·포맷·샘플 데이터·필수 필드 명시

② PROCESS
처리 규칙

변환·필터·분류 로직을 단계별로. 예외 케이스 포함

③ OUTPUT
출력 규격

파일명·시트명·컬럼 순서·인코딩 고정

④ VERIFY
검수 조건

"행 수 = 입력과 동일", "합계 일치" 등 수치 판정

02 · TEMPLATE한 장 설계서 샘플
[실습예시] 민원 분류 설계서
# 과제: 민원 1,000건 자동 분류 ## ① INPUT - 파일: ./data/민원_2025Q4.xlsx - 시트: 접수 - 필드: 접수번호, 내용, 접수일 - 총 1,083행, A~C열 ## ② PROCESS - C열 "내용"을 Ollama AI_CLASSIFY에 전달 - 라벨: 환경/교통/복지/세무/안전/기타 - 빈 셀은 "미분류"로 강제 ## ③ OUTPUT - 같은 엑셀, 신규 시트 분류결과 - 컬럼: 접수번호, 원문, 분류, 신뢰도 - 파일명: 민원_2025Q4_분류.xlsx ## ④ VERIFY - 행 수 1,083 일치 - "미분류" 비율 < 5% - 라벨 6종이 모두 최소 1건 이상 - 샘플 10건 사람 확인
TIP
숫자로 쓸 수 있는 검수 조건은 반드시 숫자로

"많이 있어야 함" → "최소 100건 이상". 검수의 판정 가능성이 품질을 결정한다.

03 · PATTERNS잘 통하는 표현 패턴
에이전트 지시문의 네 가지 숙어
01
"먼저 계획만 보여줘"
Plan 모드 유도. 검수 후 실행 지시.
02
"샘플 5건으로 먼저 테스트"
전체 1,000건 직행 금지. 소규모 검증 후 스케일.
03
"각 파일 변경 전 .bak 백업"
원본 훼손 방지. 공공 데이터에 필수.
04
"완료 후 로그 파일로 요약"
작업 종료 시 log.txt에 실행 결과 남김.
PITFALL · 설계서 없는 지시
▸ "이 엑셀 좀 정리해줘"
모호한 지시는 에이전트가 추측하게 만든다. 결과가 달라지면 책임 소재도 흐려진다.
▸ "알아서 잘 처리해줘"
에이전트는 "알아서"를 과잉 해석한다. 의도 밖 파일 수정·테스트 삽입·의존성 변경 사례 빈번.
SOURCE · 전문인재 과정 지도 원칙
"좋은 에이전트는 질문을 유도하고, 좋은 사용자는 구조로 답한다."
— 거점리더의 언어

검수 체크리스트 + 유형 ③④⑤ 재현 — 어시스트 결과와 비교한다

파이썬 버전·의존성 requirements.txt 기록

샘플 입력·샘플 출력 한 쌍 포함
