이 교재는 코딩 문법책이 아닙니다

먼저 “프로그램이 흘러가는 길”을 이해하면, AI에게 무엇을 시켜야 할지가 보입니다.

바이브코딩을 아주 쉽게 말하면
“내가 원하는 결과를 얻기 위해, 이미 존재하는 좋은 부품을 찾아 AI와 함께 조립하는 일”입니다.

요리로 비유하면

  • AI/LLM = 요리사
  • 데이터 = 식재료
  • 데이터베이스 = 냉장고
  • 라이브러리 = 조리도구
  • API = 밖에서 재료·서비스를 받아오는 통로
  • 백엔드 = 주방
  • 프론트엔드 = 손님이 보는 식탁
  • MCP = AI가 여러 도구를 같은 방식으로 쓰게 해주는 연결 규격

이 순서만 기억하세요

  1. 무엇을 만들지 정한다.
  2. 필요한 데이터가 무엇인지 찾는다.
  3. 그 데이터를 읽는 라이브러리나 API를 찾는다.
  4. 검색하기 좋은 형태로 정리한다.
  5. 검색 결과를 AI에게 넣는다.
  6. 백엔드에서 연결하고 프론트엔드에서 보여준다.
  7. 반복해서 쓸 기능은 MCP로 도구화한다.

그냥 챗봇

질문을 받고 한 번 답합니다. 외부 파일을 읽거나 실제 프로그램을 실행하지 않아도 됩니다.

질문 → AI → 답변

에이전트

AI가 상황을 보고 “무슨 도구가 필요한지” 판단합니다. 실행 결과가 예상과 다르면 다른 도구를 다시 선택할 수 있습니다.

질문 → 판단 → 도구 → 결과 → 재판단 → 답변
예: “이 폴더의 PDF를 읽어서 정책별로 분류하고 DB로 만든 뒤, 결과가 이상한 파일만 다시 파싱해줘.”라고 하면 파일 읽기, 파싱, DB 저장, 검증이 여러 번 이어집니다. 이때 AI는 작업 순서를 조정하는 역할을 합니다.

2. 에이전트AI 챔피언 고급과정 · 바이브코딩 실전

하네스는 AI에게 손과 발을 붙이는 작업대

모델 자체가 엔진이라면, 하네스(harness)는 그 엔진이 파일·터미널·브라우저·MCP·API를 쓰게 하는 실행 환경입니다.

LLM만 있을 때

  • 글을 읽고 판단한다.
  • 코드를 제안한다.
  • 답변을 만든다.
  • 하지만 실제 PC에서 파일을 열거나 명령을 실행할 권한은 없을 수 있다.

하네스가 붙으면

  • 파일 시스템을 읽는다.
  • 터미널 명령을 실행한다.
  • 브라우저를 조작한다.
  • API·MCP 도구를 호출한다.
  • 결과를 다시 AI에게 돌려준다.

강의 스케치 1 — 클라우드의 LLM과 내 컴퓨터의 하네스·브라우저·프론트엔드·백엔드를 분리해서 본 그림

그래서 코딩 에이전트가 강한 이유: AI가 “코드를 말해주는 것”에서 끝나지 않고, 실제 프로젝트 폴더를 읽고 수정하고 실행 결과까지 확인하기 때문입니다.

둘을 나누면 복잡했던 프로그램 구조가 매우 단순하게 보입니다.

프론트엔드

화면

  • 입력창, 버튼, 표, 그래프

  • 사용자가 직접 보는 영역

백엔드

처리

4. 로컬과 웹AI 챔피언 고급과정 · 바이브코딩 실전

로컬 → 검증 → 웹 배포 순서가 가장 편합니다

처음부터 클라우드에 올리면 오류 원인이 로컬 코드인지, 배포 설정인지, 인증인지 구분하기 어려워집니다.

강의 스케치 3 — 로컬 컴퓨터와 백엔드 서버, Vercel·Netlify·Cloudflare 같은 프론트/서버리스 배포 환경을 비교한 그림

2단계 · 연결

3단계 · 배포

원칙: 배포는 개발의 시작점이 아니라 검증된 조합을 다른 사람이 사용할 수 있게 옮기는 단계라고 생각하면 쉽습니다.

8. 데이터 구조AI 챔피언 고급과정 · 바이브코딩 실전

XML, JSON, CSV, SQLite, JSONB는 경쟁자가 아니라 “다른 그릇”입니다

어떤 형식이 최고인지 묻기보다, 어떤 질문을 할 것인지부터 봅니다.

형식쉽게 말하면잘 맞는 상황
XML태그로 의미와 계층을 표시RSS, 법령, 문서 구조, 표준 교환
JSON코드와 AI가 다루기 쉬운 구조API, 설정, 웹 데이터, 구조화 문서
CSV사람이 바로 보는 표DB 넣기 전 검수, 단순 목록
SQLite파일 하나짜리 SQL 데이터베이스로컬 검색, 개인 도구, 교육 실습
PostgreSQL JSONBJSON을 DB 안에서 구조적으로 저장/질의Supabase 같은 웹 프로젝트, 유연한 스키마
중요한 구분: SQLite는 보통 JSON을 TEXT로 저장하고 JSON 함수를 사용합니다. PostgreSQL/Supabase에서는 JSONB 타입을 직접 사용할 수 있습니다. 즉, “JSONB”라는 말은 DB 종류에 따라 의미가 다릅니다.

8. 데이터 구조AI 챔피언 고급과정 · 바이브코딩 실전

내가 만든 데이터베이스가 프로젝트의 차별점이 됩니다

같은 GPT, 같은 Claude를 써도 데이터가 다르면 서비스의 품질과 전문성이 달라집니다.

공개 API+나만의 정제 데이터+나만의 검색 규칙=차별화된 서비스

“남들이 가진 데이터”만 쓸 때

  • 공공 API 그대로 연결
  • 원문 문서 전체를 그대로 넣음
  • 분류체계가 없음
  • 검색 결과가 비슷해지기 쉬움

“내 데이터”를 만들 때

  • 현업에서 필요한 문서만 큐레이션
  • 부서·날짜·업무유형·근거조항 메타데이터 추가
  • 예외사례와 판단기준을 사람이 검수
  • 기관 업무 흐름에 맞는 카테고리 구성
DB는 꼭 거대한 서버가 아닙니다. 작은 프로젝트에서는 잘 정리된 XML 한 파일, JSON 묶음, CSV 폴더도 충분히 “지식베이스”가 됩니다. 핵심은 필요한 순간에 필요한 조각을 정확히 꺼낼 수 있느냐입니다.

바이브코딩의 본질을 한 문장으로

AI가 코드를 잘 써주는 시대일수록, 사람은 “무엇을 연결할지”를 더 잘 알아야 합니다.

문제↓데이터·문서·API↓파싱 라이브러리↓XML / JSON / DB↓SQL / BM25 / Fuse / 임베딩↓컨텍스트 주입↓AI / LLM↓백엔드↓프론트엔드↓배포

내 문제에 맞는 데이터, 내 데이터에 맞는 파서, 내 질문에 맞는 검색, 내 환경에 맞는 API와 라이브러리를 찾고 조합하는 능력에서 생깁니다.
