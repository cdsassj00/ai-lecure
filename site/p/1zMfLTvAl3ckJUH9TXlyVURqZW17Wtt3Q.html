[이론] LLM의 기본 상태 — 답변 생성과 실행 능력의 구분

LLM은 학습된 가중치와 현재 입력을 이용해 다음 토큰을 생성합니다. 문장을 작성하고 코드를 제안할 수 있지만, 도구가 연결되지 않은 LLM은 파일을 열거나 프로그램을 실행하지 못합니다.

1
학습 지식

학습 시점에 형성된 언어 패턴과 지식을 사용합니다.입력 — 사용자가 지금 보낸 텍스트·이미지·표.한계 — 최신 내부 문서와 PC 상태를 자동으로 알지 못합니다.

2
추론 결과

현재 입력에 이어질 가능성이 높은 출력을 만듭니다.출력 — 답변·요약·코드·분류·초안.한계 — 출력이 실제 실행 결과와 같다는 보장은 없습니다.

언어모델의 입력과 출력
INPUT
프롬프트 + 현재 컨텍스트

질문, 지침, 문서 조각, 대화기록이 입력 범위에 들어옵니다.

▼ 토큰 확률 계산
OUTPUT
텍스트·코드·도구 요청

도구 연결이 없으면 제안으로 끝나고, 연결이 있으면 실행 요청으로 이어집니다.

구분

LLM이 답을 생성하는 능력과 컴퓨터에서 작업을 실행하는 능력은 서로 다른 계층입니다.

프롬프트는 일정한 문장 공식을 채우는 양식이 아닙니다. 현재 상태에서 원하는 상태로 무엇을 바꿀지를 모델이나 에이전트에 전달하는 요청입니다. 같은 요청도 연결된 파일·도구·권한·이전 작업 상태에 따라 실행 범위가 달라집니다.

[이론] 컨텍스트의 구성 — 지침·자료·대화·실행 상태

1
지침과 기준

기관 규칙, 작성 양식, 보안 기준, 프로젝트별 작업 지침입니다.예 — 개인정보 마스킹, 원본 보존, 출력 서식.확인 — 현재 작업에 적용되는 우선순위가 분명한가.

2
문서와 데이터

파일, DB 조회 결과, 검색 문단, 표, 코드처럼 작업의 근거가 되는 자료입니다.예 — 회의록, 매뉴얼, XLSX, 오류 로그.확인 — 최신성·권한·출처가 유지되는가.

3
대화와 결정 기록

이전 요청, 수정 지시, 채택한 선택지, 제외한 대안이 현재 판단에 영향을 줍니다.예 — 제목 확정, 색상 선택, 변경 금지 범위.확인 — 오래된 지시와 최신 지시를 구분하는가.

4
실행 상태와 결과

현재 파일 내용, 터미널 출력, 테스트 결과, 화면 상태가 다음 행동의 근거입니다.예 — 생성된 파일, 실패 명령, 렌더 이미지.확인 — 추측 대신 실제 결과를 다시 읽었는가.

정리

컨텍스트 엔지니어링은 설명을 길게 쓰는 기술이 아니라, 현재 작업에 필요한 근거와 상태를 선택해 모델이 사용할 수 있게 만드는 일입니다.

[구분] 컨텍스트 창과 컨텍스트 설계 — 용량과 선택의 차이

구분뜻실무 영향대응
컨텍스트 창한 번에 모델이 읽을 수 있는 토큰 범위긴 문서·대화·코드가 누적되면 중요한 정보가 밀려나거나 비용과 지연이 증가합니다.문서 분할, 대화 요약, 필요한 파일만 선택합니다.
컨텍스트 구성현재 요청에 넣을 근거와 상태의 조합같은 모델도 어떤 지침·문서·실행 결과를 넣는지에 따라 판단과 출력이 달라집니다.현재 작업과 직접 관련된 근거를 우선합니다.
컨텍스트 갱신도구 실행 후 새 결과를 다시 입력에 반영파일을 수정하거나 코드를 실행한 뒤 결과를 읽지 않으면 다음 판단이 이전 상태에 머뭅니다.실행 → 결과 읽기 → 다음 행동 순서를 유지합니다.
컨텍스트 오염오래되거나 충돌하는 지시·자료가 섞인 상태폐지 문서, 과거 요구, 관련 없는 로그가 현재 작업을 잘못 이끌 수 있습니다.최신성·우선순위·권한·출처를 표시합니다.
판단

큰 컨텍스트 창은 많은 자료를 넣을 수 있게 하지만, 필요한 자료를 선별하고 갱신하는 설계를 대신하지 않습니다.

인터랙티브 도식에서 하네스는 클라우드 LLM과 내 컴퓨터 사이를 연결합니다. 모델의 판단을 OS·파일·브라우저·Python·DB의 실제 동작으로 바꾸고, 실행 결과를 다시 모델에 돌려줍니다.

LLM 대형 언어모델
  • 적합 긴 문서 이해, 규정 비교, 복잡한 작성
  • 장점 폭넓은 지식과 높은 지시 이해
  • 비용 API 비용·지연·외부 전송 검토
  • 검증 기관 문서 샘플로 정확도 시험
SLM 소형 언어모델
  • 적합 분류, 추출, 짧은 요약, 도구 호출
  • 장점 빠른 응답, 로컬 실행, 낮은 비용
  • 한계 복잡한 추론과 긴 문서 품질
  • 검증 반복 업무별 최소 품질 확인
혼합 운영 라우팅
  • 분기 단순 작업은 SLM, 복잡한 작업은 LLM
  • 보안 민감 자료는 로컬, 공개 자료는 API
  • 비용 캐시·사용량 제한·월 비용 상한
  • 운영 실패 시 대체 모델과 사람 검토
