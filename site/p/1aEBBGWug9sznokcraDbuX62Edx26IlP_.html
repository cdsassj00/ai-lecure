[체험] 코딩 에이전트란 — 도구를 띄워 놓고 만지며 이해한다

코딩 에이전트는 사람이 자연어로 지시하면, 모델이 스스로 파일을 읽고 쓰고 명령을 실행해 일을 끝까지 수행하는 프로그램입니다. 설명만 듣지 않고, 직접 한 줄 지시를 넣어 보며 동작을 눈으로 확인합니다.

·
일반 챗봇과의 차이

챗봇은 글로 답만 합니다. 코딩 에이전트는 답하는 데 그치지 않고 직접 파일을 만들고 고치고 실행해 결과물을 남깁니다. 화면에서 파일이 실제로 생기는 것을 직접 봅니다.

·
동작 구조 — 하네스

모델에게 도구를 쥐여 주고 반복 실행시키는 구조를 하네스라고 부릅니다. Antigravity·Claude Code 모두 이 구조 위에서 동작합니다. 하네스 세부 설정은 CTO 심화 세션에서 다룹니다.

에이전트가 일하는 방식 — 네 단계의 반복
1
묻기 — "지금 무엇을 할까요?"를 모델에게 보낸다
2
고르기 — 모델이 "이 도구를 쓰겠다"고 정한다
3
확인 후 실행 — 권한을 확인하고 그 도구를 실행한다
4
알려주기 — 실행 결과를 모델에게 다시 전달한다
↺ 모델이 "끝"이라고 할 때까지 1~4를 반복
직접 해보기

지금 Antigravity에 간단한 지시를 한 줄 넣어 봅니다. 사람은 무엇을 원하는지만 말하고, 도구를 고르고 실행하는 반복은 에이전트가 맡는다는 것을 화면으로 직접 확인합니다.

핵심 개념 세 가지
1
CLAUDE.md프로젝트 메모 파일

에이전트가 세션 시작 시 자동으로 읽는 문서. 프로젝트 목적·파일 구조·금지 사항을 적어 두면 매번 설명하지 않아도 맥락을 이해하고 작업한다. 설계 방법은 다음 세션에서 다룬다.

2
권한 확인 구조

파일 생성·수정·명령 실행 전에 항상 확인을 묻는다. y(이번만 허용) / a(항상 허용) / n(거부)로 응답한다. 위험한 작업은 반드시 먼저 묻는다.

3
무료 플랜 시작

Anthropic 계정으로 로그인하면 API 키 없이도 월 사용량 한도 내 무료 사용 가능. 한도 초과 시 유료 플랜 또는 API 키를 연결한다.

첫 사용 팁

가장 먼저 헷갈리는 것은 "어느 폴더에서 실행하느냐"입니다. 항상 작업할 프로젝트 폴더로 이동한 뒤 claude를 실행합니다. 에이전트는 그 폴더 안의 파일만 인식하고 수정합니다.

[실습] 바이브코딩이란 — 코드를 쓰지 않고 말로 만든다

바이브코딩은 코드를 직접 작성하지 않고, 원하는 결과를 자연어로 설명해 에이전트가 만들게 하는 방식입니다. 결과를 보고 말로 고쳐 나가는 반복이 핵심입니다. Claude Code 대화창이 곧 작업 도구입니다.

1
무엇을 만드나

간단한 사내용 미니 도구나 웹페이지를 만듭니다. 일정 계산기, 설문 정리 화면, 팀 현황 대시보드, 비교 분석 리포트 화면 등이 대표적입니다. 한 번도 코드를 쓰지 않고 만듭니다.

2
어떻게 지시하나

목적·내용·보이는 모습을 한 번에 설명합니다. "팀원 5명의 이번 달 업무 현황을 카드 형식으로 보여 주는 웹페이지를 만들어 줘"처럼 구체적으로 적을수록 한 번에 원하는 결과가 나옵니다.

3
어떻게 고치나

결과를 보고 마음에 안 드는 부분을 말로 다시 요청합니다. "배경을 흰색으로 바꿔 줘", "글씨가 너무 작아, 18px로 키워 줘"처럼 화면을 보며 말로 수정하면 에이전트가 그 부분만 고쳐 다시 보여 줍니다.

역할 분담 — 사람과 에이전트
사람이 하는 일
무엇을 원하는지 설명한다

어떻게 보였으면 좋겠는지, 어떤 내용이 들어가야 하는지 말로 전합니다. 결과를 보고 고칠 곳을 짚는 것도 사람의 역할입니다. 코드를 읽을 필요가 없습니다.

▼ 지시를 넘긴다
Claude Code(에이전트)가 하는 일
코드를 쓰고 파일로 저장한다

설명을 HTML·Python·JavaScript 코드로 변환하고 파일을 만들어 바로 열어 볼 수 있게 저장합니다. 실행 결과까지 확인하고 오류가 있으면 스스로 수정합니다.

관찰 포인트

한 줄도 직접 코딩하지 않았는데 실제로 동작하는 결과물이 나옵니다. 중요한 것은 코드를 읽는 능력이 아니라, 무엇을 원하는지 분명히 설명하는 능력입니다.

[실습] 바이브코딩 진행 절차 — 요청 · 생성 · 확인 · 수정

한 장짜리 웹페이지를 예로, 네 단계로 진행합니다. 처음부터 완벽한 지시를 작성할 필요가 없습니다. 대략 만든 뒤 말로 다듬어 가는 것이 바이브코딩의 본질입니다.

① 요청
만들 것 설명

"무엇을, 어떤 내용으로, 어떻게 보이게" Claude Code 대화창에 한국어로 적습니다. 구체적일수록 한 번에 가까워지며, 짧아도 됩니다 — 이후 말로 고쳐 나가면 됩니다.

② 생성
에이전트가 작성

에이전트가 코드를 작성하고 파일을 저장합니다. 권한 요청(파일 생성 여부)이 오면 y로 허용합니다. 이 과정에서 사람은 기다리기만 하면 됩니다. 오류가 생기면 에이전트가 스스로 수정합니다.

③ 확인
결과 화면 보기

만들어진 파일을 브라우저나 터미널로 열어 실제로 동작하는지 확인합니다. 코드를 읽지 않아도 됩니다. 눈으로 보이는 결과물만 확인하면 됩니다.

④ 수정
말로 고치기

"여기 색을 바꿔 줘", "이 항목을 위로 올려 줘"처럼 다시 요청해 원하는 모습으로 다듬습니다. ③과 ④를 원하는 모습이 될 때까지 반복합니다.

[실습] 문서 자동화 — 임원 업무에 바로 닿는 네 영역

임원 업무에서 반복되는 문서 작업을 에이전트에게 시킬 수 있습니다. 네 영역 중 본인 업무와 가장 가까운 하나를 골라, 실제 자료를 넣어 직접 실습합니다.

보고서 초안
  • 입력회의 메모·요점·핵심 자료 묶음
  • 지시 예"이 자료로 임원 보고용 초안을 목차 포함해 작성해 줘"
  • 작업목차 구성, 섹션별 문단 작성, 요약 문장 추가
  • 수정어색한 표현·빠진 내용 말로 추가 요청
  • 산출즉시 검토 가능한 보고서 초안 한 편
회의록 정리
  • 입력받아쓴 회의 내용 또는 음성 텍스트
  • 지시 예"결정사항·할 일·담당자를 표로 분리해 줘"
  • 작업안건별 정리, 결정·액션·담당자 분류
  • 수정빠진 항목·오류 말로 수정 요청
  • 산출바로 발송 가능한 회의록 문서
데이터 표 분석
  • 입력엑셀·CSV 표 또는 복사한 숫자
  • 지시 예"전월 대비 증감과 주목할 지표를 요약해 줘"
  • 작업요약 통계, 증감 계산, 이상값 감지
  • 수정특정 항목 추가 분석 말로 요청
  • 산출표·차트와 한 줄 해석 문서
자료 조사 요약
  • 입력조사 주제·참고 출처·URL 목록
  • 지시 예"이 주제로 최근 동향 3~5개를 요약해 줘"
  • 작업웹 검색, 본문 정리, 출처 분류
  • 수정특정 항목 심층 조사 말로 요청
  • 산출출처 링크 붙은 요약 리포트
공통 흐름

네 영역 모두 지시 → 생성 → 확인 → 수정이라는 같은 흐름입니다. Claude Code 대화창에 자료를 붙여 넣거나 파일 경로를 알려 주면, 에이전트가 작업을 대신 처리합니다.

[실습] 진행 절차와 간단한 스킬 — 한 번 정리해 다시 쓴다

같은 작업을 매번 똑같이 시키려면, 지시를 한 번 글로 정리해 두고 재사용합니다. 이렇게 저장해 둔 작업 방식을 스킬이라고 합니다.

① 선택
업무 하나 고르기

네 영역 중 본인 업무와 가장 가까운 하나를 정합니다. 첫 실습은 친숙한 영역부터 시작하는 것이 효과적입니다.

② 지시
요청 작성

입력 자료와 원하는 결과 형식을 함께 적습니다. "이 자료로 보고서 초안을 목차 포함해 작성해 줘"처럼 구체적으로 쓸수록 한 번에 원하는 결과가 나옵니다.

③ 확인
결과 점검

나온 결과를 보고 빠진 곳·어색한 표현·고칠 곳을 말로 다듬습니다. 수정이 반복될수록 지시가 점점 정교해집니다.

④ 저장
스킬로 저장

잘 된 지시를 스킬 파일에 저장해 두면 다음에 같은 작업을 할 때 처음부터 다시 쓰지 않고 바로 꺼내 씁니다.

지침 기준 문서
  • 늘 지켜야 할 톤·형식·금지 사항을 한곳에 적어 둔 문서
  • 에이전트가 세션 시작 시 자동으로 읽어 반영한다
  • "보고서는 3단 구조로, 숫자는 천 단위 콤마 표기" 같은 내용
  • 매번 재지시 없이도 일관된 결과가 나온다
스킬 반복 절차
  • 특정 업무의 지시 방법을 파일로 저장해 둔 묶음
  • 필요할 때 불러 쓰면 매번 같은 품질로 처리된다
  • 팀 전체가 같은 스킬을 공유하면 품질이 통일된다
  • 한 번 만들어 두면 영구 재사용 가능하다
재사용의 의미

한 번 잘 정리해 두면, 다음부터는 긴 설명 없이 같은 결과를 얻습니다. 사람마다 들쭉날쭉하던 결과물의 기준이 하나로 맞춰집니다.

[정리] 조직 도입 시 점검할 지점 — 보안 · 비용 · 거버넌스 · 시작점

실무 도입을 검토할 때 임원이 짚어야 할 지점은 네 가지입니다. 기술의 깊이가 아니라 판단의 기준에 해당합니다.

보안
  • 어떤 자료가 외부 서버로 전송되는가 확인
  • 사내 전용·격리 환경 또는 On-premise 사용 여부
  • 민감 자료(개인정보·계약서) 처리 규칙 마련
  • 모델 학습에 사내 데이터가 사용되는지 확인
  • 팀별 접근 권한과 사용 범위 사전 정의
비용
  • 사용량 기반 토큰·API 요금 체계 이해
  • 인원·사용 빈도에 따른 월별 비용 예측
  • 무료 플랜 vs 유료 플랜 기능 차이 파악
  • 절감 효과(인력·시간)와 도구 비용 비교
  • 파일럿 팀 기준 실제 사용량 측정 후 확대
거버넌스
  • 누가 무엇에 쓰는지 용도별 정리
  • 에이전트 결과물의 검수 책임 명시
  • 공통 지침·스킬 파일의 작성·관리 주체
  • 부서별 사용 가이드라인 및 금지 사항 공지
  • 정기 점검과 품질 피드백 체계 수립
시작점
  • 위험 낮고 반복 많은 업무 한두 가지부터
  • 3~5명 소규모 팀에서 먼저 파일럿 실시
  • 2~4주 효과 측정 후 확대 여부 결정
  • 성공 사례를 내부에 공유해 확산 모멘텀 확보
  • 전면 도입은 파일럿 결과 확인 후 단계적으로
권고

전면 도입을 서두르기보다, 위험이 낮고 반복이 많은 업무 한두 가지를 작은 팀에서 먼저 시험해 효과를 확인하는 방식을 권합니다. 오늘 실습한 문서 자동화가 그 출발점으로 적합합니다.

강의 요약

01

코딩 에이전트는 자연어 지시를 받아 스스로 파일을 읽고 쓰고 실행하며 일을 끝까지 수행하는 프로그램이다. 일반 챗봇과 달리 도구를 반복 사용한다.

02

실습은 무료로 쓸 수 있는 Antigravity로 시작해 코딩 에이전트의 동작을 직접 체험했다. Claude Code는 터미널 기반 에이전트로, 스킬·MCP 설정과 CLAUDE.md 맥락 파일까지 함께 다뤘다.

03

바이브코딩 — 코드를 직접 쓰지 않고 말로 만들고, 결과를 보며 말로 고쳐 나간다. 코드 지식보다 원하는 것을 분명히 설명하는 능력이 더 중요하다.

04

문서 자동화 — 보고서·회의록·데이터·자료조사 같은 반복 업무를 에이전트에게 시키고, 자주 쓰는 지시는 스킬로 저장해 같은 품질로 다시 쓴다.
