01.

현재 AI 기술의 위치와 흐름 파악

Bard·PaLM 시기부터 GPT 시대를 거쳐 에이전트 시대로 넘어온 NLP 진화 흐름을 정리한다. MicroGPT를 통해 트랜스포머의 Q·K·V와 멀티헤드 구조를 시각적으로 확인한다. 프롬프트 → 컨텍스트 → 하네스로 이어지는 입력 양식의 변화도 함께 다룬다. 모델의 내부 동작을 깊이 다루지 않으며, ‘왜 지금 이 과정이 필요한가’ 를 이해하는 수준까지가 목표다.

다루는 범위NLP 흐름, 트랜스포머 개념, 프롬프트 진화, 프론티어 모델 비교
다루지 않는 것수식 유도, 모델 학습·파인튜닝 실습

언어모델은 ‘답하는 도구’에서 ‘일하는 동료’로 변화했다.

2017년 트랜스포머 등장 이후 약 9년간의 변화를 3단계로 정리한다. Pre-LLM 시기(BERT·PaLM), LLM 시기(ChatGPT 이후), 에이전트 시기(현재). 각 단계의 대표 모델·핵심 변화·우리에게 의미하는 바를 한 번에 확인한다.

2017 — 2022

Pre-LLM 시기 · BERT / Bard / PaLM

트랜스포머가 등장하고 인코더 계열(BERT)·디코더 계열(GPT) 두 갈래로 갈렸다. 모델은 ‘완성품’이 아닌 ‘부품’이었고, 도메인마다 파인튜닝이 필수였다.

대표BERT, GPT-2, T5, PaLM, Bard
사용처분류·추출·번역 — 대부분 백엔드
사용자개발자·연구자 중심. 일반인은 거의 접하지 못함
2022.11 — 2024

LLM 시기 · ChatGPT 이후

GPT-3.5에서 GPT-4, Claude, Gemini가 연이어 등장. 한 모델이 글쓰기·요약·번역·코드·추론을 모두 처리하면서 ‘AI 사용’이 일상화됐다.

대표ChatGPT, Claude 3, Gemini 1.5

2024 — 현재

에이전트 시기 · 일을 통째로 위임

모델이 도구를 호출(function calling, MCP)하고, 스스로 루프를 돌며(reasoning), 다른 에이전트와 협업(A2A, MoA)한다. Claude Code·Cursor·Antigravity 같은 도구는 ‘답변’이 아닌 ‘완성된 결과물’을 돌려준다.

사용자가 모델에 일을 시키는 방식은 3단계로 변해왔다.

한 번의 질문(Prompt) → 업무 맥락의 묶음(Context) → 작업 환경 자체(Harness). 모델 진화와 같은 곡선을 그린다. 6회차부터 본격적으로 다루는 에이전트 도구는 모두 ‘하네스’ 단계의 도구다.

① Prompt — 한 번의 질문
② Context — 업무 맥락의 묶음
③ Harness — 작업 환경 자체
정의
한 번의 질문과 답

“요약해줘”, “번역해줘” 한 마디로 입력과 출력이 끝난다. 가장 단순한 형태이며, 매번 처음부터 맥락을 다시 입력해야 한다.

역할·자료·제약·예시 패키지

한 번의 설정으로 여러 번 같은 맥락에서 작업할 수 있다. 사용자는 ‘질문자’ 가 아닌 ‘업무 환경 설계자’ 가 된다.

도구·메모리·서브 에이전트 결합

파일 시스템·터미널·외부 API·다른 에이전트가 모두 결합된 ‘작업 환경’. 에이전트는 이 환경 안에서 스스로 일한다.

대표 도구

chat.openai.com 첫 화면, 일회성 채팅

Custom GPTs, Claude Projects · Skills, Gemini Gems, 시스템 프롬프트

Claude Code, Cursor, Antigravity, Codex CLI, OpenCode

사용 시점

일회성 작업, 즉답이 필요한 단순 요청

반복적 업무, 일관된 톤·형식이 필요한 작업

코드 작성·서비스 개발 같이 도구·파일 조작이 필요한 작업

본 과정에서의 위치

1~3회차: ① · ② 단계 학습. 프롬프트와 컨텍스트(Custom GPT, Projects)를 자유롭게 다루는 수준까지.

본 과정에서의 위치

6~8회차: ③ 단계 본격 학습. Claude Code·Cursor·Antigravity 같은 에이전트 도구로 풀스택 개발.

Unit 02 · MicroGPT 로 트랜스포머 구조 확인

왜 LLM은 다음 단어를 예측할 수 있는가 ─ 핵심 구조 3가지를 확인한다.

트랜스포머의 핵심 메커니즘인 Self-Attention(Q·K·V)과 Multi-Head 구조를 200줄 분량의 MicroGPT 코드로 시각화한다. 모델 구현이 목적이 아니라, 거점리더가 동료에게 ‘왜 이런 답이 나오는가’ 를 설명할 수 있는 최소한의 직관을 갖추는 것이 목적이다.

핵심 비유: 한 문장을 여러 명이 동시에 다른 관점으로 읽는다

한 명은 문법을, 한 명은 주제를, 한 명은 시제를 본다. 각 관점의 결과를 모아 다음 단어를 결정한다. 이것이 멀티헤드 어텐션의 직관이다.

왜 이걸 다루는가

거점리더가 동료에게 “왜 이 답이 나왔는가” 라는 질문을 받았을 때, 환각·문맥 길이·온도 같은 개념을 비유로 설명할 수 있는 최소한의 직관이 필요하다. 트랜스포머를 직접 구현하기 위함이 아니다.

# MicroGPT — 200줄 분량 GPT 시연 class Head(nn.Module): def forward(self, x): q = self.query(x) # 질의 k = self.key(x) # 색인 v = self.value(x) # 의미 w = q @ k.T / sqrt(d) w = softmax(w) # 가중치 return w @ v # 결합 출력

Workshop · 강의 후반 워크샵 활동 3가지

1차시 후반부에 진행되는 3가지 워크샵 ─ 환경 세팅 · 아카이브 가입 · 미션 카드 작성.

1차시는 강의 중심이지만, 후반부 약 70분은 워크샵 시간이다. 8주 과정 동안 매끄러운 학습이 가능하도록 도구·계정·저장소를 정렬하고, 본 과정의 핵심 산출물인 거점 미션 카드를 작성한다. 모든 활동은 개인 노트북에서 진행한다.

기획 · 재료 창고 · 워크플로우

Closing · 1차시 정리

1차시 정리 ─ 3가지 핵심과 다음 차시 안내.

현재 AI 기술의 위치를 확인했고, 9가지 공공 구현 유형으로 도착 지점을 그렸으며, 외부/내부망 학습 절차와 도구 환경을 정렬했다. 거점 미션 카드 1장으로 8주 학습 방향이 개인별로 명확해졌다. 2차시부터 본격 도구 학습이 시작된다.

01.

지형 파악은 비판적 검토의 출발점

프론티어 5갈래를 직접 비교한 사람만이 소버린·공통기반 LLM의 적합성을 판단할 수 있다. 2회차에서 50선 도구 투어로 적응력을 확장한다.

02.

9유형은 본 과정의 분류 체계

모든 실습은 9유형 중 하나에 분류된다. 같은 문제도 어떤 유형으로 배포하느냐에 따라 구현 방식이 달라진다. 8회차 캡스톤은 9유형까지 도달하는 회차다.

03.

거점리더는 설계자, 개발은 에이전트가 담당

거점리더는 코드를 직접 작성하지 않는다. 아키텍처를 설계하고 에이전트에 위임한다. 최종 산출물은 코드가 아닌 아키텍처 1장이다. 그 시작이 오늘 작성한 거점 미션 카드다.
