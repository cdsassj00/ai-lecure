전체 흐름

흐름은 LLM 단독에서 시작해, LLM+Tool+Loop Agent로 확장되고, 이후 LLM/작업공간이 내 PC 안으로 들어옵니다. 하네스가 내부 도구와 외부 도구 호출을 연결합니다.

핵심: 하네스는 단순 통로가 아니라 tool call, 권한, 실행, 결과 반환을 묶는 연결 계층입니다.

FRAME 0

흐름 재정의

전체 흐름은 “클라우드 LLM이 브릿지를 통해 PC를 조작한다”보다, “LLM/작업공간이 내 PC 안으로 들어오고, 하네스가 내·외부 도구 호출을 연결한다”로 보는 편이 자연스럽습니다.

FRAME 1

LLM 단독

처음에는 LLM이 답변을 생성합니다. 텍스트를 이해하고 추론하고 설명할 수 있지만, 이 상태만으로는 파일을 열거나 프로그램을 실행하거나 웹을 조작하지 않습니다.

FRAME 2

LLM + Tool + Loop = Agent

에이전트는 LLM에 도구와 반복 루프가 붙은 구조입니다. 계획하고, 도구를 호출하고, 결과를 관찰하고, 다시 수정하는 루프가 생기면서 작업 수행 능력이 생깁니다.

FRAME 3

LLM이 내 PC로 들어온다

코딩 에이전트나 로컬 자동화 환경에서는 LLM이 단순 클라우드 대화창에 머무르지 않고, 내 PC의 작업공간, 파일시스템, 터미널, IDE와 연결됩니다.

FRAME 4

하네스가 연결한다

하네스는 LLM이 바로 OS나 웹을 만지는 것이 아니라, 정해진 인터페이스를 통해 tool call을 전달하고 실행 결과를 다시 돌려받게 하는 연결 계층입니다.

FRAME 5

내부 도구 호출

내부 도구는 OS 명령, 파이썬, 로컬 파일, 엑셀, PDF, 브라우저 제어처럼 내 PC 안에 있는 실행 자원입니다. 하네스가 이를 안전한 호출 단위로 묶어줍니다.

FRAME 6

외부 도구 호출

외부 도구는 외부문서, 웹, 외부 사이트, API, SaaS입니다. 내 PC의 하네스는 내부 도구뿐 아니라 외부 도구 호출도 함께 중계합니다.

FRAME 7

최종 정리

결론적으로 LLM은 판단과 계획을 만들고, Agent Loop는 작업을 반복 수행하며, 내 PC의 하네스는 내부·외부 도구 호출을 연결합니다. 그래서 “답변 생성”이 “실행 자동화”가 됩니다.

수정 흐름 반영 완료

이 버전은 LLM → LLM+Tool+Loop Agent → Local LLM/PC Workspace → Harness → Internal/External Tool Calling 순서로 다시 구성했습니다.
