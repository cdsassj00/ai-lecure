이 시간이 끝날 때, 수강생은 두 개의 질문에 자기 언어로 답할 수 있어야 한다.

하나는 ‘지금 우리는 어디에 서 있는가’ 라는 위치 감각이고, 다른 하나는 ‘8주 뒤 우리는 무엇을 만들 수 있게 되는가’ 라는 도착지의 그림이다. 이 두 좌표 사이에 8회차의 모든 실습이 놓인다.

01.

지금 우리가 서 있는 기술적 위치는 어디인가

Bard와 PaLM에서 시작해 GPT 시대를 거쳐 에이전트 시대로 넘어온 짧지만 격렬한 진화사를 한 호흡에 정리한다. MicroGPT를 간단히 뜯어 트랜스포머의 Q·K·V와 멀티헤드를 시각적으로 체감하고, 프롬프트 → 컨텍스트 → 하네스로 이어지는 입력 양식의 진화도 같은 맥락에서 짚는다. 깊이 파지는 않는다. 이 과정이 ‘왜 지금’ 필요한지 납득시키는 것이 목적이다.

다루는 것NLP 트렌드, 트랜스포머 개념, 프롬프트 진화, 모델 지형도
다루지 않는 것수식, 미분, 모델 학습, 파인튜닝 디테일
02.

8주 뒤 우리는 무엇을 만들 수 있게 되는가

공공 현장에서 실제로 도입 가능한 ‘민첩한 AI’ 9가지 구현 유형을 개괄로 본다. AI가 준 파이썬을 내부망에서 실행하는 가장 단순한 1유형에서부터 API·MCP 기반 풀스택 멀티 에이전트 서비스인 9유형까지, 각 유형이 어느 회차에 어떤 모드(어시스트 / 에이전트)로 등장하는지 머릿속 지도를 미리 그린다. 그 지도 위에서 자신이 가져갈 거점 미션 1개를 1차시 안에 선언한다.

이번 회차 산출물현업 과제 1개 + 목표 유형 1개 = 거점 미션 카드

언어모델은 ‘답하는 도구’에서 ‘일하는 동료’로,
프롬프트는 ‘질문’에서 ‘업무 환경’으로 진화했다.

왼쪽은 모델의 진화, 오른쪽은 우리가 모델에게 일을 시키는 방식의 진화다. 두 진화는 같은 곡선을 그린다 — 한 번에 한 마디씩 묻던 것에서, 환경 전체를 설계해 맡기는 쪽으로.

2017 — 2022

Pre-LLM · BERT / Bard / PaLM

트랜스포머가 등장하고, 인코더 계열(BERT)·디코더 계열(GPT) 두 갈래가 갈렸다. 모델은 ‘완성품’이 아닌 ‘부품’이었고, 도메인마다 파인튜닝이 필수였다.

  • 분류·추출이 주된 사용처
  • 일반 사용자에게는 거의 보이지 않음
2022.11 — 2024

LLM 시대 · ChatGPT 충격

GPT-3.5 → GPT-4, Claude, Gemini가 연달아 등장. 한 모델 안에서 글쓰기·요약·번역·코드·추론이 모두 처리되며, ‘AI를 쓴다’는 행위가 일상에 들어왔다.

  • RLHF, 멀티모달, 긴 컨텍스트
  • 프롬프트 엔지니어링이라는 새 직무
2024 — 현재

Agent 시대 · 일을 통째로 맡긴다

모델이 도구를 호출하고 (function calling, MCP), 스스로 루프를 돌며 (reasoning), 다른 에이전트와 협업한다 (A2A, MoA). Claude Code·Cursor·Antigravity 같은 도구는 ‘대답’이 아닌 ‘완성된 결과물’을 돌려준다. 사용자의 역할은 작업자에서 기획자·설계자로 이동한다.

Unit 02 · 트랜스포머를 ‘체감’ 한다

왜 이 모델은 글의 다음 단어를 이렇게 잘 맞히는가 ─ 그 메커니즘을 손가락으로 짚어본다.

우리는 모델을 만들 사람이 아니다. 그러나 거점리더는 ‘왜 그런 답이 나오는가’를 말로 설명할 수 있어야 한다. 수식 대신 주의(Attention) 라는 한 단어와, Q·K·V 라는 세 글자, 그리고 ‘여러 개의 시선(Multi-head)’ 이라는 비유. 이 세 가지면 충분하다.

‘여러 명의 독자가 한 문장을 동시에 읽는다’ — 그게 멀티헤드다.

한 명은 문법을, 한 명은 주제를, 한 명은 시제를 본다. 이들의 관점을 모아 다음 단어를 결정한다. 우리가 ‘LLM은 통계적 앵무새’라는 말에 한 발 거리를 두는 이유다.

Why we touch this

거점리더가 동료에게 “왜 이 답이 나왔어?”라는 질문을 받았을 때, 환각·문맥 길이·온도 같은 개념을 비유로 풀 수 있는 최소한의 직관을 갖기 위해서다. 절대 트랜스포머를 ‘구현’ 하기 위해서가 아니다.

# MicroGPT — 200줄짜리 GPT 시연 class Head(nn.Module): def forward(self, x): q = self.query(x) # 내 궁금증 k = self.key(x) # 색인표 v = self.value(x) # 의미 내용 w = q @ k.T / sqrt(d) w = softmax(w) # 누구를 볼까 return w @ v # 모아서 출력

학습 · 실험 · 코드 수령의 영역

Unit 07 · 공용 아카이브 · 거점 미션 선언

개인 PC에 갇힌 산출물은 자산이 아니다 ─ 1차시의 마지막 행위는 ‘함께 쌓는 자리’를 여는 것이다.

공용 발굴 노트와 아카이브 저장소를 1차시에 함께 개설한다. 그리고 각자 거점 미션 카드 1장을 작성한다 — 부서로 돌아가 풀고 싶은 현업 과제 1개와, 9가지 유형 중 도달할 목표 유형 1개. 이 카드는 8회차 캡스톤 발표에서 다시 펼쳐진다.

공용 발굴 노트 · 아카이브 저장소

Closing · 1차시 정리

우리는 ‘쓰는 사람’으로 들어와 ‘되게 만드는 사람’으로 나간다 ─ 1차시는 좌표 측정의 시간이었다.

기술적 위치를 짚었고, 도착지의 9유형 지도를 받았고, 외부/내부 동선을 머리에 넣었고, 도구를 정렬했고, 거점 미션 1장을 선언했다. 다음 7주는 이 좌표를 도구·역량·문화로 채워가는 일이다.

01.

지형을 안다는 것은 비판할 수 있다는 것

프론티어 5갈래를 직접 써본 사람만이 소버린·공통기반의 타당성을 말할 수 있다. 1차시는 그 ‘말할 권리’의 출발점이다. 2회차에서 50선 투어로 적응력을 체질화한다.

02.

9유형은 본 과정의 좌표 격자다

모든 실습은 9유형 중 어딘가에 떨어진다. 같은 문제도 어떤 유형으로 배포하느냐에 따라 만드는 방식이 달라진다. 8회차 캡스톤은 9번 유형까지 도달하는 자리다.

03.

거점리더는 설계자이지 개발자가 아니다

코드를 손으로 쓰지 않는다. 청사진을 그리고 에이전트에게 위임한다. 산출물은 코드가 아닌 아키텍처 1장이다. 그 시작이 오늘의 거점 미션 카드다.
