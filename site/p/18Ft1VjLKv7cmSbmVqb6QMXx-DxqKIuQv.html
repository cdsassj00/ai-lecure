LLM AS A BRAIN

LLM은 강력한 두뇌지만, 두뇌만으로는 일이 끝나지 않습니다

읽고 이해합니다

문서 맥락, 질문 의도, 표와 코드의 구조를 파악합니다.

  • 요약·추출·비교
  • 맥락 해석
  • 질문 재구성

그러나 파일을 스스로 찾지 못합니다.

판단하고 생성합니다

대안을 비교하고 초안·분류·계획·프로그래밍 코드를 만듭니다.

  • 문장과 보고서
  • 의사결정 보조
  • 코드와 명령

그러나 결과를 직접 실행하지 못합니다.

언어를 번역합니다

업무 요구를 컴퓨터가 실행할 프로그래밍 언어로 바꿉니다.

  • 자연어 → 구조
  • 요구 → 코드
  • 오류 → 수정

그러나 권한과 도구가 없으면 멈춥니다.

LLM은 무엇을 할지 판단할 수 있지만, 현실의 파일·프로그램·시스템을 움직일 손발은 없습니다.

RAG IS A TOOL, NOT A STRATEGY

기관 자료를 잘 답하는 챗봇이 모든 문제의 답은 아닙니다

겉으로 보이는 요구 실제 병목 RAG만으로 부족한 이유 필요한 조합
규정을 빨리 찾고 싶다 찾은 뒤 판단·결재·등록 반복 검색 후 행동이 사람에게 남음 검색 + 절차 + 입력 자동화
상담 답변을 잘하고 싶다 분류·기록·후속 조치 누락 답변 품질과 업무 완료는 다름 LLM + 워크플로우 + 검토
보고서를 빨리 쓰고 싶다 숫자 취합과 출처 검증 문장보다 데이터 준비가 병목 파일 자동화 + 검증 + 생성
기관 지식을 공유하고 싶다 부서별 절차·양식·책임 차이 검색만으로 절차를 바꾸지 못함 업무 분석 + 시스템 연결
RAG는 찾고 답하는 문제에 강합니다. AX는 업무가 끝나는 지점까지 설계해야 합니다.
