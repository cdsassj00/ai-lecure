Semantic Search

초보자를 위한 시맨틱 검색 입문

키워드 검색부터 Query Expansion, SPLADE, Embedding, Hybrid Search까지

검색의 목적은 단순히 문서를 찾는 것이 아니라, 질문과 관련된 근거를 골라 AI에게 전달하는 것입니다. 이 교재는 “같은 단어”를 찾는 검색과 “같은 뜻”을 찾는 검색의 차이를 이해하고, Context Injection에 연결하는 방법을 쉽게 설명합니다.

PART 1 · 검색의 기본

같은 단어를 찾는 것과 같은 뜻을 찾는 것은 다르다

사용자가 “공무원 업무 자동화”라고 검색했는데 문서에는 “반복 행정절차를 AI가 대신 처리한다”라고 적혀 있을 수 있습니다. 단어는 다르지만 사람은 같은 주제라고 이해합니다. 시맨틱 검색은 이런 의미 관계를 검색에 반영하는 방법입니다.

1장 키워드 검색과 시맨틱 검색

키워드 검색은 문서 안에 검색어와 같거나 비슷한 단어가 있는지를 봅니다. 시맨틱 검색은 단어가 달라도 의미가 비슷한지를 봅니다.

질문문서 표현키워드 검색시맨틱 검색
공무원 업무 자동화공무원 반복업무 자동화잘 찾음잘 찾음
공무원 업무 자동화반복 행정절차를 AI가 대신 처리놓칠 수 있음찾을 가능성이 높음
자동차 사고차량 충돌약함강함

따라서 시맨틱 검색은 “문장을 이해해서 답한다”는 뜻이 아니라, 질문과 문서 사이의 의미적 관련성을 계산해 더 관련 있는 문서를 찾는 검색 방식입니다.

2장 FTS와 BM25는 왜 필요한가

시맨틱 검색을 이해하려면 먼저 전통적인 검색을 알아야 합니다. FTS는 Full-Text Search의 약자로, 문서를 단어 단위로 미리 색인해 빠르게 찾는 방식입니다. BM25는 검색 결과 중 어떤 문서가 더 중요한지를 점수화해 순위를 정합니다.

방식쉽게 말하면강점
LIKE문자열 포함 여부가장 단순함
Fuse.js글자 모양이 비슷한지 비교오타·부분일치
FTS단어 색인을 만들어 검색빠른 본문 검색
BM25관련 문서를 점수순으로 정렬검색 결과 순위

중요한 점은 BM25도 매우 강력한 검색이지만, 기본 상태에서는 “자동차”와 “차량”처럼 단어가 다른 동의어를 자동으로 이해하지 못한다는 것입니다.

PART 2 · 임베딩 없는 시맨틱 검색

검색어를 똑똑하게 만들면 벡터 DB 없이도 품질을 높일 수 있다

문서를 모두 벡터화하지 않고도 의미 검색에 가까운 결과를 만들 수 있습니다. 대표적인 방법이 동의어 확장, Query Expansion, 형태소 분석, N-gram, Sparse Semantic Search입니다.

3장 Query Expansion · 질문을 검색어로 확장한다

사용자의 질문을 그대로 한 번 검색하는 대신, 관련된 표현을 여러 개 만들어 검색하는 방법입니다. LLM을 답변 생성기가 아니라 검색어 생성기로 사용할 수도 있습니다.

질문:
예산 낭비 사업을 찾아줘

확장 검색어:
예산 낭비
예산 과다
불용액
집행률 저조
성과 미달
중복 사업

이 확장 검색어를 FTS나 BM25에 넣으면 “예산 낭비”라는 표현이 원문에 없어도 관련 문서를 찾을 가능성이 높아집니다.

사용자 질문

핵심어 추출

동의어·관련어 확장

FTS·BM25 검색

4장 동의어·형태소·N-gram

동의어 사전은 “자동차=차량”, “공무원=공직자”, “AI=인공지능”처럼 같은 뜻의 표현을 미리 연결합니다. 업무 용어가 명확한 기관 검색에서 설명 가능성이 높고 통제하기 쉽습니다.

형태소 분석은 한국어 문장에서 핵심 단위를 분리합니다. “행정업무를 자동화했습니다”를 “행정 / 업무 / 자동화”처럼 나누면 검색 품질이 좋아질 수 있습니다.

N-gram은 문자열을 2~3글자씩 잘라 비교합니다. 띄어쓰기, 복합어, 오타가 있는 한국어 검색에서 보조적으로 유용합니다. PostgreSQL의 pg_trgm도 비슷한 목적에 사용할 수 있습니다.

방법잘하는 것
동의어업무 용어·표준어 연결
형태소 분석한국어 핵심어 분리
N-gram / Trigram띄어쓰기·부분일치·오타 보정

5장 SPLADE · 키워드와 의미의 중간

SPLADE는 Sparse Semantic Search 계열의 대표적인 방식입니다. 문장을 단순히 그대로 저장하지 않고, 관련성이 높은 단어까지 확장해 각 단어에 가중치를 줍니다.

원문:
자동차 사고 보험

확장 예:
자동차  2.4
사고    2.2
보험    2.0
차량    1.5
충돌    1.3
보상    1.1
청구    0.9

Dense Embedding처럼 수백 개 숫자 좌표를 사용하는 대신 단어 기반의 Sparse Vector를 사용합니다. 따라서 키워드 기반 검색의 설명 가능성을 어느 정도 유지하면서 의미 확장을 얻을 수 있습니다.

PART 3 · 임베딩 시맨틱 검색

문장을 숫자 벡터로 바꾸어 의미의 거리를 비교한다

임베딩은 문장이나 문서를 수백 개의 숫자로 변환합니다. 의미가 비슷한 문장은 벡터 공간에서도 가까운 위치에 놓이도록 학습됩니다.

6장 Embedding · 문장을 숫자로 바꾼다

자동차 사고
→ [0.21, -0.45, 0.92, ...]

차량 충돌
→ [0.20, -0.42, 0.89, ...]

두 문장의 숫자 배열이 가깝다면 의미도 비슷하다고 판단합니다. 이때 자주 사용하는 계산 중 하나가 cosine similarity입니다.

문서가 많아지면 임베딩을 저장하고 빠르게 찾기 위해 pgvector, Qdrant, Pinecone, Milvus, Weaviate, Chroma, FAISS 같은 벡터 검색 도구를 사용할 수 있습니다.

문서를 작은 단위로 나눈다

각 문서를 임베딩한다

질문도 임베딩한다

가까운 문서를 찾는다

7장 Sparse와 Dense를 비교한다

항목SparseDense
대표 방식BM25, SPLADEEmbedding
표현단어별 가중치숫자 벡터
정확 키워드강함상대적으로 약할 수 있음
의미 유사도중~강강함
설명 가능성높음낮음

업무 시스템에서는 어느 한쪽이 항상 우월한 것이 아닙니다. 문서번호, 기관명, 사업명처럼 정확한 단어가 중요한 검색은 Sparse/키워드 방식이 강하고, 민원·상담·회의록처럼 표현이 다양한 데이터는 Dense Semantic Search가 유리할 수 있습니다.

PART 4 · Hybrid Search와 Context Injection

검색 기술보다 중요한 것은 필요한 근거를 골라 모델에 넣는 과정이다

실무에서는 키워드 검색과 시맨틱 검색을 함께 사용한 뒤, 상위 결과만 Context로 전달하는 구조가 강력합니다.

8장 Hybrid Search · 키워드와 의미를 함께 본다

Hybrid Search는 BM25 같은 키워드 검색과 Embedding 같은 시맨틱 검색을 함께 사용합니다. 두 방식이 잘하는 영역이 다르기 때문입니다.

질문우선 강한 방식
AI-2026-00451 문서Exact / BM25
성과가 좋지 않았던 사업Semantic Search
행안부 AI 사업 중 복지 분야SQL + BM25 + Semantic

두 결과를 합칠 때 RRF(Reciprocal Rank Fusion) 같은 순위 결합 방식을 쓸 수 있습니다. 초보자는 먼저 “키워드 상위 5개 + 시맨틱 상위 5개 → 중복 제거”만 해도 하이브리드의 개념을 이해할 수 있습니다.

9장 검색 결과를 Context Injection으로 연결한다

검색은 최종 답변이 아닙니다. 검색으로 얻은 문서 중 질문과 관련된 근거만 골라 모델 입력에 넣는 것이 Context Injection입니다.

사용자 질문

키워드·시맨틱 검색

상위 근거 선택

질문+근거를 모델 입력에 전달

모델이 근거를 설명

질문:
최근 3년간 지자체 AI 사업 중 복지 분야 사업을 찾아줘.

검색:
1. 날짜 조건 → SQL
2. AI/인공지능/복지/돌봄 → FTS·BM25
3. 필요하면 시맨틱 검색
4. 상위 근거와 출처 선택
5. 선택된 근거만 모델에 전달

이 구조에서는 AI가 데이터베이스 전체를 읽는 것이 아닙니다. 프로그램이 먼저 필요한 근거를 좁히고, 모델에는 질문과 관련된 범위만 전달합니다.

10장 초보자의 선택 순서

단계먼저 배울 것이유
1문자열 검색검색의 기본 이해
2FTS + BM25실제 검색엔진 구조 이해
3Query Expansion벡터 DB 없이 의미 확장
4SPLADE / Sparse키워드와 의미의 중간 이해
5EmbeddingDense Semantic Search 이해
6Hybrid Search실무형 검색 구성

처음부터 벡터 데이터베이스를 구축할 필요는 없습니다. SQLite FTS5 + BM25로 시작하고, 실제로 “같은 뜻인데 단어가 달라서 못 찾는 문제”가 생기면 Query Expansion이나 Embedding을 추가하는 것이 이해하기 쉽습니다.

핵심 정리: 키워드 검색은 같은 말을 잘 찾고, 시맨틱 검색은 같은 뜻을 잘 찾습니다. Hybrid Search는 둘을 합칩니다. Context Injection은 그 검색 결과를 AI의 답변 근거로 넣는 과정입니다.
