[관점] 공공 AX 정책과 현장 업무의 간극 — 정책 단위와 업무 단위의 구분

공공 AX 정책은 플랫폼 구축, 데이터센터, 전사 시스템처럼 큰 단위로 발표됩니다. 그러나 수강생이 매일 하는 일은 한글 공문 기안, 엑셀 취합, 민원 답변, 회의록 정리 같은 작은 단위입니다.

1
정책 단위 교육의 한계

사례가 크고 멀어서 수강생이 자기 업무와 연결하지 못합니다. 예 — 전사 챗봇 구축 사례만 다루면 강의 직후 이어질 실습 접점이 없습니다.

2
업무 단위 교육의 조건

수강생이 오늘 오후에 해볼 수 있는 크기로 과제를 자릅니다. 예 — 30분짜리 부서 취합 업무 1건을 실습 재료로 가져와 그 자리에서 처리해 봅니다.

같은 "AI 도입"의 두 층위
정책 단위
플랫폼 · 데이터센터 · 전사 시스템

예산·조직 단위로 움직이고, 실무자 개인이 좌우할 수 없습니다.

▼ 강의는 이 아래에서 출발합니다
업무 단위
공문 기안 · 엑셀 취합 · 민원 답변 · 회의록

실무자가 오늘 바꿀 수 있고, 실습으로 바로 이어지는 층위입니다.

정리

강사는 두 층위를 구분해 설명하고, 실습은 반드시 업무 단위에서 출발합니다. 정책 이야기는 배경 설명 10분을 넘기지 않습니다.

[관점] 도구의 전유 — 기존 도구를 원래 용도 밖에서 쓰는 방법

전유(Appropriation)는 이미 설치된 도구를 원래 용도 밖의 업무 도구로 끌어다 쓰는 것입니다. 새 시스템 도입도 보안 결재도 필요 없어, 공공 환경에서 실행 가능성이 가장 높은 출발점입니다.

1
HTML 파일을 업무 도구로

브라우저만 있으면 실행되는 단일 HTML 파일로 계산기·체크리스트·시뮬레이터를 만듭니다.예 — "단일 HTML 파일로 OO 계산기를 만들어 달라"고 요청해 받은 파일을 더블클릭으로 실행. 설치·서버·인터넷 없이 동작해 망분리 PC에서도 씁니다.

2
브라우저 개발자도구(F12)를 자동화 도구로

브라우저 내장 콘솔에서 자바스크립트 몇 줄로 화면의 표를 추출하거나 반복 입력을 대신합니다.예 — 게시판 목록에서 콘솔 코드 한 번으로 제목·날짜를 표로 복사. 코드는 AI에게 화면 구조를 설명하고 받아서 쓰며 외부 설치가 없습니다.

3
그림자 자동화 리스크

개인이 만든 자동화가 부서 공유·감사 범위 밖에서 돌아가는 상태로, 전유를 가르칠 때 반드시 함께 다룹니다.예 — 담당자만 아는 취합 파일이 인사이동 후 방치. 부서 공유·사용법 문서화·인수인계 등록을 실습 마무리에 포함합니다.

정리

강사는 신규 도입 제안이 아니라 이미 깔려 있는 도구의 재사용부터 시연합니다. 수강생의 첫 성공 경험이 여기서 나옵니다.

[관점] 가능 여부와 책임 범위 — 약관·보안·감사 기준의 구분

시연에서 "된다"는 것과 기관에서 "책임지고 쓸 수 있다"는 것은 다른 문제입니다. 이 구분 없이 기능만 보여주면 수강생이 보안 사고의 출발점이 될 수 있습니다.

1
되는 것 기술적으로 가능한 범위

기능 자체는 대부분 됩니다. 내부 문서를 올리면 요약되고 민원 데이터를 넣으면 분류됩니다.예 — 회의록 업로드 후 "부서별 조치사항을 표로 정리해 달라". 다만 "된다"는 사실만으로 업무 적용을 권하지 않습니다.

2
책임지고 쓸 수 있는 것 규정을 통과하는 범위

보안지침·서비스 약관·개인정보보호법·감사 대응까지 통과해야 업무에 쓸 수 있습니다.확인 — 개인정보·비공개 자료 입력 금지, 입력 데이터 학습 여부와 제외(옵트아웃) 설정, 기관 지침 존재. 하나라도 미확인이면 가상 자료로 처리합니다.

3
강의에서의 처리 방식

모든 실습 앞에 "이 실습에 넣어도 되는 데이터"를 먼저 명시합니다.예 — 실제 민원 대신 강사 제공 가상 데이터로 실습. 산출물은 부서로 가져갈 "입력 가능/불가 판단표" 1장입니다.

정리

실습 자료는 가상 데이터로 제공하고, 실제 업무 적용 시의 판단 기준을 별도 장(4부 윤리·보안)에서 다시 다룹니다.

[관점] 강사의 포지션 — 기능 시연자와 교육 설계자의 구분, M.A.S.T.E.R 6요소

도구 기능 설명은 유튜브에도 있습니다. 강사의 값어치는 수강생의 업무·환경·수준에 맞게 과정을 설계하고, 문제 정의부터 산출물 적용까지 안내하는 데서 나옵니다. 그 준비 항목을 6가지로 정리합니다.

요소내용점검 질문
M 메시지·브랜딩전문 분야, 강의 철학, 차별점을 문장으로 정리해 둡니다."나는 어떤 강사인가"에 한 줄로 답할 수 있는가.
A 도입·몰입 설계첫 10분의 사례·시연·질문으로 수강생을 자기 업무 생각으로 끌어옵니다.도입 시연이 수강생 직군과 연결되는가.
S 구조·도구 라이브러리자료·도구·프롬프트를 모듈 단위로 쌓아 재사용합니다.지난 강의 자료를 30분 안에 재조합할 수 있는가.
T 과정 설계모듈을 조합해 대상·시간·환경에 맞는 커리큘럼을 만듭니다.같은 주제로 3시간판·6시간판을 만들 수 있는가.
E 자료·비주얼표·도식·실습 화면 중심으로 강의안을 구성합니다.슬라이드에 복붙 가능한 실제 프롬프트가 있는가.

언제 심해지나

방식정의공공 적용 조건
sLM
경량 언어모델		소형 언어모델을 기관 서버나 PC에 설치해 자체 구동하는 방식입니다.망분리 환경에서 Ollama 등으로 구동 가능합니다. 성능은 상용 대비 제한적이므로 요약·분류 등 좁은 용도부터 검토합니다.
파인튜닝
추가 학습		기존 모델에 기관 데이터를 추가 학습시켜 말투·양식을 맞추는 방식입니다.데이터 정제, 학습 비용, 유지보수 부담이 큽니다. 대부분의 요구는 파인튜닝 전에 프롬프트 설계나 RAG로 먼저 해결되는지 확인합니다.
RAG
검색 결합 생성		질문이 들어오면 기관 문서를 검색해 근거로 붙인 뒤 답을 생성하는 방식입니다.문서 최신화가 관건입니다. 규정·매뉴얼·업무편람 질의응답에 우선 적용하고, 답변에 근거 문서 표시를 요구합니다.

기관 요구의 대부분은 파인튜닝이 아니라 RAG 또는 프롬프트 설계로 해결됩니다. 강사는 이 판단 순서를 담당자에게 제시할 수 있어야 합니다.

[원리] 에이전트와 MCP — 도구 연결 구조와 실패 요인

에이전트는 LLM이 도구(검색·파일·프로그램 실행)를 호출하고 결과를 받아 다음 행동을 정하는 반복 구조입니다. MCP(Model Context Protocol)는 이 도구 연결을 표준화한 규격입니다.

1
실패 요인 ① 반복 폭주

반복할수록 입력이 길어져 비용이 급증하고, 종료 조건이 없으면 멈추지 않습니다. 확인 — 최대 반복 횟수·시간 제한을 걸고 시연합니다.

2
실패 요인 ② 오류 증폭

앞 단계의 잘못된 출력이 다음 단계의 근거가 되어 오류가 굳어집니다. 확인 — 중간 산출물을 사람이 검토하는 지점을 설계에 넣습니다.

에이전트의 반복 구조
1
목표 입력 — 사람이 과제와 권한 범위를 정해 줍니다.
2
도구 선택·호출 — 모델이 검색·파일 읽기·실행 중 필요한 것을 고릅니다.
3
결과 반영 — 도구 결과를 입력에 추가하고 다음 행동을 정합니다.
4
완료 판단 — 목표 달성 여부를 확인하고 보고합니다.
미완료면 2번으로 반복 — 그래서 종료 조건이 필수입니다
시연 기준

시연은 반드시 작은 과제(파일 3개 정리 수준)로 하고, 부여한 권한 범위를 화면으로 먼저 보여준 뒤 시작합니다.

2
검증 책임

표기·저작권

AI 활용 사실의 표기 기준과 생성물의 저작권 이슈를 안내합니다.예 — 대외 발간물의 AI 활용 표기, 생성 이미지의 상업적 사용 조건.확인 — 타인 저작물을 통째로 넣어 변형 생성하는 요청은 하지 않도록 지도합니다.

4
결과 책임과 공유

자동화 산출물의 오류도 담당자 책임입니다. 공유와 문서화로 그림자 자동화를 방지합니다.예 — 자동 취합 도구는 사용법 1장 문서와 함께 부서에 공유.확인 — 인수인계 목록에 자동화 도구 항목을 추가합니다.
