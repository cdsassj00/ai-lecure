엑셀 vs 구글 스프레드시트 — 핵심 차이 통합 데모

워크플로우 개요

구글 스프레드시트는 파일을 주고받지 않는다. 저장 버튼이 없고(자동 저장), 같은 시트를 여러 명이 동시에 편집하며, 모든 변경이 버전 기록에 남는다. 본 모듈은 기능을 하나씩 나열하지 않는다. 실제 엑셀 파일 하나를 업로드해 구글 시트로 변환 → 두 명이 동시 편집 → 버전 기록으로 복원하는 통합 데모로 차이를 한 번에 확인한다. 이어지는 두 장에서 기능·함수 차이를 비교표로 정리한다.

  • 자동 저장·버전 기록 — Ctrl+S 불필요. 파일 > 버전 기록에서 과거 시점으로 복원 가능
  • 동시 편집 — 여러 명이 같은 시트를 편집. 커서 색으로 편집 위치 표시
  • 공유 = 링크 권한 — 파일 전송 대신 뷰어/댓글/편집자 권한 링크로 협업
  • 스마트칩 — @입력으로 사람·파일·날짜를 셀 안에 객체로 삽입
  • 웹 게시 — 파일 > 공유 > 웹에 게시 — 시트를 URL로 공개 (M5에서 사용)
통합 데모 순서
  • ① 엑셀 파일(.xlsx)을 드라이브에 업로드 → Google Sheets로 열기
  • ② 참가자 2명에게 편집 권한 링크 전달 → 동시 편집 확인
  • ③ 셀 몇 개를 수정 → 파일 > 버전 기록 → 수정 전 시점 복원
  • ④ @입력으로 담당자 스마트칩 삽입
  • ⑤ Gemini 사이드패널(✦) 열기 — 다음 실습 카드 P-01로 연결
사전 학습자료 대체 범위메뉴 구조, 맞춤 서식·조건부 서식 상세, 데이터 검증·드롭다운 생성, 공유 권한 설정표 — 교육 1주 전 PDF 전달, 당일 관련 질문은 실습 중 개별 대응

M2. 구글 전용 함수 심화 — Gemini로 수식 생성 — 1.0H

구글 전용 함수 3종 — QUERY · IMPORTRANGE · ARRAYFORMULA

워크플로우 개요

앞 장 비교표에서 확인한 대로, 세 함수는 엑셀에 대응물이 없거나 동작이 다른 구글 전용 함수다. 본 모듈은 이 세 함수에 집중하되 문법 암기는 하지 않는다 — Gemini에 자연어로 요청해 수식을 받고, 에러가 나면 에러 메시지를 그대로 붙여 수정을 요청한다. 여러분이 익힐 것은 세 함수가 각각 무엇을 할 수 있는지 파악하는 것이다. 그래야 무엇을 요청할지 알 수 있다.

함수기능실무 시나리오
IMPORTRANGE다른 스프레드시트 파일의 데이터를 실시간으로 가져온다 — 파일 간 연결팀별로 관리하는 시트 5개를 한 파일로 실시간 취합
QUERYSELECT·WHERE·GROUP BY — SQL 방식으로 데이터를 추출·집계·정렬한다부서별·월별 처리 건수 집계표를 수식 한 줄로 생성
ARRAYFORMULA수식 하나가 열 전체에 자동 확장 — 행이 늘어나도 수식 복사 불필요매일 데이터가 추가되는 시트의 파생 열(등급·구분) 자동 계산
[실제 프롬프트 — Gemini 사이드패널에 그대로 입력]'응답' 시트의 A:F 데이터에서, C열(부서)별로 E열(금액)의 합계와 건수를 구하는 QUERY 수식을 만들어줘. 결과는 합계 내림차순으로 정렬해줘.
[에러 발생 시 — 에러 메시지를 그대로 붙인다]이 수식에서 "QUERY에서 쿼리를 파싱할 수 없음: NO_COLUMN: C" 에러가 나. 원인을 찾아서 고친 수식을 줘. 내 시트의 헤더는 1행에 있어.
요청 원칙① 시트 이름·열 범위·헤더 위치를 명시한다 ② 원하는 결과의 형태(집계 기준·정렬)를 구체적으로 쓴다 ③ 에러는 메시지 전문을 복사해 붙인다 — 이 세 가지만 지키면 수식 문법을 몰라도 된다

  • 구글 서비스 연결 — 시트 → Gmail 발송, 캘린더 등록, 드라이브 파일 생성
  • 트리거 자동 실행 — 매일 오전 9시, 폼 제출 시, 시트 수정 시 자동 작동
  • 사용자 메뉴 배포 — 매크로를 시트 상단 메뉴 버튼으로 등록, 팀원 누구나 클릭으로 실행
Apps Script 제어 범위 (VBA와 비교)

M4. 시트 백엔드 — 구조 이해

시트를 백엔드로 쓰는 웹앱 구조 — 4단계

워크플로우 개요

소규모 웹앱에 별도 서버와 데이터베이스가 필요하지 않은 구조를 다룬다. 구글 시트가 데이터 저장소, Apps Script 웹앱 배포가 API 역할을 한다. HTML 페이지에서 입력한 데이터가 시트에 행으로 쌓이고, 시트의 데이터가 HTML 화면에 표시된다. 운영 비용 0원. HTML과 Apps Script 코드는 생성형 AI(Gemini·Claude)로 작성한다.

단계작업내용
①시트 준비헤더만 있는 빈 시트 생성 (예: 이름 | 부서 | 요청내용 | 시각)
②Apps Script 작성doGet(읽기)·doPost(쓰기) 함수를 AI로 생성해 붙여넣기
③웹앱 배포배포 > 새 배포 > 웹 앱 → 접속 URL 발급
④HTML 연결발급 URL로 fetch하는 HTML 페이지를 AI로 생성 → 완성
  • 사례 A — 사내 설문·신청 접수 페이지 (★) — 시트 = 응답 저장소
  • 사례 B — 팀 업무 현황판 (★★) — 시트 = 현황 데이터 원본, HTML은 조회 화면
  • 사례 C — 비품·회의실 예약 미니앱 (★★★) — 시트 = 예약 기록 장부
적용 기준
  • 동시 사용자 수십 명 이하 · 사내 소규모 도구 → 시트 백엔드로 충분
  • 대외 서비스 · 대용량 · 권한 관리 필요 → 정식 DB(Supabase 등) 사용
  • 민감 정보(개인정보·인사)는 시트 공개 범위 설정을 반드시 점검
