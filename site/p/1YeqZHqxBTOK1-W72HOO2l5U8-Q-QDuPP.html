PART A-1 · CHATGPT 고급 기능 ① · PROJECTS · CUSTOM GPTs
ChatGPT 고급 기능 — Projects와 Custom GPTs
거점리더가 ChatGPT에서 먼저 살펴볼 두 가지 고급 기능입니다. 첫째, Projects는 대화·파일·지침을 하나의 프로젝트로 묶어 두는 작업 공간입니다. 프로젝트에 올려 둔 파일은 이후 모든 대화에서 자동 참조됩니다. 둘째, Custom GPTs는 시스템 프롬프트·파일·Actions를 묶어 재사용하는 '나만의 GPT'입니다. 부서 업무에 맞는 챗봇을 만들어 동료에게 공유할 수 있습니다. 두 기능 모두 개인용이 아니라 부서 단위로 설정해 사용합니다.
FEATURE 01 · PROJECTS
채팅 · 파일 · 지침을
하나로 묶는 작업 공간
프로젝트 안에서는 대화 간 맥락이 자동 유지됩니다. 파일을 올려두면 이후 모든 대화가 그것을 참조합니다. 부서 지침 · 샘플 보고서 · 금칙어 세트를 한 프로젝트에 두면 동료가 진입 비용 없이 같은 기준의 답변을 받습니다.
질문 템플릿 5개를 고정 메시지로 상단에 배치하고, 주 1회 업데이트 담당자를 정해두면 자산이 됩니다.
FEATURE 02 · CUSTOM GPTs
시스템 프롬프트 + 파일 + Actions
= 재사용 단위 "나만의 GPT"
GPT Store에서 다른 사용자가 만든 것도 가져다 쓸 수 있습니다. 공공에서는 "민원 분류 GPT" · "예산 검토 GPT" 같은 업무 특화 GPT를 거점리더가 만들어 부서에 배포합니다. Actions는 외부 API 호출 기능이지만 8차시 MCP로 대체되는 방향입니다.
Custom GPT는 좋은 프롬프트를 묶어 동료에게 공유하는 가장 빠른 방법입니다.
DEPLOYMENT LENS
부서 단위로
운영하는 이유
Projects와 Custom GPTs를 개인 도구로만 사용하면 본인만 활용하게 됩니다. 부서 단위로 설정해 두면 동료가 같은 환경에서 같은 기준의 답변을 받을 수 있습니다. 부서 지침 PDF, 샘플 보고서 3건, 금칙어 목록을 한 프로젝트에 미리 올려 두는 데 약 30분이 걸립니다.
민감 파일 업로드는 주의해야 합니다. OpenAI 서버에 저장되므로 감사·분쟁 소지가 있는 문서는 비식별화 후에 사용합니다.

ChatGPT 고급 기능 셋째·넷째 — Canvas와 Agent 모드
ChatGPT의 세 번째·네 번째 고급 기능입니다. 첫째, Canvas는 ChatGPT 채팅 옆에 열리는 편집판으로, 문단·코드 블록 단위로 수정할 수 있습니다. 외부 연결 없이 긴 문서나 코드를 다듬는 작업 공간입니다. 둘째, Agent 모드는 ChatGPT가 스스로 웹 탐색·Drive 접근·파일 처리를 순차 실행하는 멀티스텝 자동화 기능으로, 외부 도구 연결이 전제됩니다. 두 기능은 용도가 다르므로 분리해서 이해해야 합니다.

ChatGPT 고급 기능 다섯째·여섯째·일곱째 — o1/o3 추론 · 메모리 · Deep Research
ChatGPT의 다섯째부터 일곱째 고급 기능입니다. 첫째, o1/o3는 OpenAI의 추론 전용 모델로, 응답 전에 '생각하는 시간'을 사용합니다. 법령 해석이나 조건 충돌 점검 같은 다단계 판단에 강합니다. 둘째, Memory는 사용자 정보와 맥락을 대화 사이에 자동 기억합니다. 부서나 담당 업무를 한 번만 알려 주면 이후 자동 반영됩니다. 셋째, Deep Research는 여러 웹 소스를 자동 검색해 종합 보고서를 작성합니다. 정책 벤치마킹 초안 작성에 적합합니다. 모든 업무에 o3를 쓰면 비용과 속도가 무너지므로 업무 특성에 따라 모델을 나눠 사용하는 것이 중요합니다.
KICK 05 · o1 / o3 REASONING

추론 모델
응답 시간·비용이 올라가므로 판단 근거가 필요한 업무에만 투입합니다. 법령 해석 · 다단계 판단 · 조건 충돌 점검처럼 "왜 그런가"를 설명해야 하는 일에 강합니다. 단순 요약·분류엔 일반 모델로 충분합니다.
모든 업무에 o3를 쓰면 비용과 속도 모두 무너집니다. 추론 분기 규칙을 부서 위키에 고정합니다.

민감 업무에서는 메모리를 끄고 사용합니다. 저장된 메모리는 주기적으로 점검합니다.

빠른 파악 루틴 6단계

17:10~17:30 시간에 정리하는 항목입니다. 6단계(IN/OUT · FREE · WHERE · API/MCP · INSERT · LINK)를 본인 업무 맥락에 맞춰 정리하고, 공용 저장소의 체크리스트로 업로드합니다. 새 AI 서비스가 등장할 때마다 같은 6단계로 한 칸씩 채워 약 5분 안에 도입 여부를 판단할 수 있습니다.

STEP 01 · IN → OUT
무엇을 받아 무엇을 내보내는가
입력 형식·출력 포맷·품질 기준을 한 줄로 적습니다. 여기서 막힌다면 그 도구가 무엇을 하는지 아직 파악되지 않은 상태입니다.
STEP 02 · FREE
무료로 쓸 수 있는가 · 제한은?
일일 크레딧 · 워터마크 · 내보내기 제한 확인. "무료" 표시만 보고 도입 금지 — 실제 제약을 확인하지 않으면 재작업.
STEP 03 · WHERE
데이터가 어디 저장되는가
미국 · 유럽 · 한국 · 로컬 중 어디인가. 공공에서는 이 칸이 가장 먼저 검토됩니다. 답이 나오지 않으면 다음 칸으로 넘어가지 않습니다.
STEP 04 · API · MCP
API가 있는가 · MCP 서버는?
다른 도구와 결합 가능성을 판단합니다. API·MCP가 없으면 "단품용"으로 분류합니다. 있으면 워크플로우 조립 후보.
STEP 05 · WHERE · USE
내 업무의 어느 단계에 끼우나
현재 업무 흐름의 어느 단계를 대체하거나 강화할 것인가. 업무 흐름을 먼저 단계로 나눈 뒤에 빈칸을 찾습니다.
STEP 06 · LINK
이미 쓰는 도구와 어떻게 연결되나
상위 단계 · 하위 단계 도구와 포맷 호환 여부. 파일 형식 · 인증 · 복붙 편의성. 결합이 매끄러우면 실제 사용률이 높습니다.

빠른 파악 루틴 체크리스트 — 새 AI 서비스 출현 시 빠르게 판단하는 핵심 항목
6단계 표준(IN/OUT·FREE·WHERE·API/MCP·INSERT·LINK)을 기준선으로, 자기 업무 맥락에 맞는 핵심 항목으로 추립니다. 공공 부서는 "데이터 위치"·"비식별화 필요 여부"·"감사 로그 가능성" 항목이 상위 3순위에 들어가는 경우가 많습니다. 추린 항목은 체크리스트 한 파일로 작성해 공용 저장소에 올립니다. 새 AI 서비스가 등장할 때 이 파일을 열어 한 칸씩 답을 채우면 5분 안에 도입 가부 판단이 끝납니다.
CHECKLIST CORE 6루틴 표준 6항목 — 여기서 5~7개로 추립니다
항목내용
① IN → OUT입력 형식 · 출력 포맷 · 품질 기준 한 줄
② FREE 범위일일 크레딧 · 워터마크 · 내보내기 제한
③ WHERE데이터 저장 위치 (미국·유럽·한국·로컬)
④ API · MCP다른 도구와 결합 가능성
⑤ INSERT내 업무의 어느 단계에 끼우나
⑥ LINK이미 쓰는 도구와 어떻게 연결되나
추리기 원칙
자기 업무 맥락에 가장 중요한 5~7개 선택

전부 6개 그대로 써도 되고, 업무 특성에 따라 항목을 추가·삭제해도 됩니다. 공공 부서는 "데이터 위치"가 최상단이 되는 경우가 많습니다.

ADD-ON공공 맥락 추가 항목 후보
기본 6항목 외에 공공 맥락에서 자주 추가되는 항목들입니다. 비식별화 기준, 감사 로그, 계정 분리가 대표적입니다. 핵심 항목 안에 함께 넣어 작성합니다.
ADD 01 · 비식별화 필요 여부
업로드 전 가려야 할 필드가 있는가
개인정보·민감 숫자·내부 식별자를 제거한 후 업로드 가능한지 판단. 비식별화가 불가능하면 ZONE A(완전 로컬)로만 분류.
ADD 02 · 로그·재현 가능성
누가 언제 어떤 입력으로 실행했는지 추적 가능한가
공공 감사 대응. 프롬프트·시드·버전을 기록할 수단이 있는지 확인. 없으면 감사 대응이 어렵습니다.
ADD 03 · 계정 분리 가능성
업무용·개인용 계정을 분리할 수 있는가
메모리·학습 옵션이 개인 계정에 묶여 있으면 업무 계정과 분리해야 합니다. 분리가 어려운 서비스는 즐겨찾기 상위 제외.

Ollama 구동 스크린샷 1장 — 로컬 LLM 4대 도구 중 1개 이상 응답 실행 결과
A-5 실습 결과물을 기록으로 남깁니다. Ollama · LM Studio · AnythingLLM · MSTY 중 최소 Ollama는 반드시 설치합니다. 설치 → 모델 pull → 한 문장 질의 → 응답까지 한 화면에 캡처합니다. 5회차 VBA+sLLM 자동화의 사전 점검도 함께 됩니다.
STEP 01 · INSTALL
ollama.com에서
설치 파일 다운로드
사전 준비 단계에서 이미 다운로드를 마쳤어야 합니다. Windows · macOS · Linux 각 OS 설치 후 터미널에서 ollama --version으로 확인. 디스크 20GB 이상, GPU 없어도 무방.
사내망 방화벽이 설치를 막는 경우 A-5 실습 시간 내 해결 — 강사 지원 대상.
STEP 02 · PULL + RUN
ollama run llama3
(또는 qwen2 · gemma)
최초 실행 시 자동으로 모델을 내려받습니다. Llama 4·Qwen 3·Gemma 중 한 개를 골라 pull하면 충분합니다. 모델 크기는 4~8GB 내외입니다. 프롬프트 창이 뜨면 한국어 질의를 입력합니다.
소형 모델은 번역·요약·간단 분류에 제한적이지만 완전 로컬이라는 가치가 큽니다.
STEP 03 · SCREENSHOT
응답 화면을
한 장으로 캡처
명령어, 모델명, 질의, 응답이 모두 보이도록 한 화면에 담습니다. 이 이미지가 실습 ③의 결과물입니다. 공유 폴더에 추천 도구 10가지·체크리스트와 함께 등록합니다.

실습 양식 · 15MIN
AI 도구 추천 목록 — 1줄 설명 · 사용처 · 강점 · 제한 + 확장 4칸
커리큘럼 필수 4칸(1줄 설명·사용처·강점·제한)에 공공 운영 확장 4칸을 더한 8칸 표준 양식입니다. 카드 1장이면 충분합니다. 공유 폴더에 정리되면 3회차 워크플로우 실습의 구성 요소가 됩니다.
8 칸 양식필수 4칸 + 운영 확장 4칸
칸무엇을 쓰는가
① 도구 이름도구명 + 10 카테고리 중 하나
② 1줄 설명"무엇을 받아 무엇을 내보내는가" 한 문장 (필수)
③ 사용처자기 업무 어느 단계에 끼우는가 (필수)
④ 강점다른 도구 대비 차별점 1~2줄 (필수)
⑤ 제한무료 범위 · 데이터 위치 · 공공 제약 (필수)
⑥ 단계 연결상위 단계 도구 → [이 도구] → 하위 단계 도구
⑦ 비식별화업로드 전 가려야 할 필드 명시
⑧ 적용 과제 연결1회차에 선정한 현업 적용 과제에 어떻게 기여하는가
작성 가이드카드 1장 5~8분 · 10장 40~60분
빠른 파악 루틴으로 메모해 둔 내용을 카드 양식에 옮겨 담습니다. 핵심은 '사용처'와 '단계 연결'입니다. 이 두 항목이 단품 추천을 흐름 제안으로 바꾸는 전환점이 됩니다.
자주 막히는 항목 01
'단계 연결' 칸이 공백
현재 업무 흐름을 단계로 나누지 못한 경우입니다. 먼저 업무 흐름을 4~6단계로 분해한 뒤 도구가 들어갈 칸을 정합니다. 흐름 분해가 선행 작업입니다.
자주 막히는 항목 02
'비식별화' 회피
'나중에 보자'고 미루지 않습니다. 외부 전송 전 가려야 할 필드를 한 줄이라도 명시합니다. 해당 없으면 '해당 없음'이라고 적습니다.
NEXT · 공유 폴더
완성된 10장은 공유 폴더에 즉시 등록합니다. 3회차 메타 프롬프트와 워크플로우 실습에서 구성 요소로 활용됩니다. 오늘의 카드 10장이 다음 주 워크플로우 10가지의 출발점입니다.

카드 공유의 초점은 "무슨 도구를 골랐나"가 아니라 "왜 그 사용처인가"다
추천 도구 목록를 돌아가며 공유·피드백하는 블록입니다. 도구 이름 나열은 짧은 시간에 끝납니다. 핵심은 현재 업무의 어느 지점에 왜 이 도구를 꽂았는지의 설명이며, 발표는 짧게 진행합니다. 같은 카테고리 대안·비식별화 필요성·내부망 대체(Ollama·Whisper 로컬) 가능성까지 교차 점검해 빠른 파악 체크리스트의 누락 항목을 서로 보강합니다.

TIME BUDGET

짧아야 핵심이 드러납니다. 배경 설명을 줄이고 "왜 이 조합인가"로 바로 들어가는 발표가 좋은 발표. 질의 3분이 설계의 약점을 드러냅니다.

ARCHIVE등록 원칙 + 다음 차시 연결
추천 목록 + 5분 체크리스트를 공유 폴더에 즉시 등록합니다. 다른 수강생의 카드도 열람 가능 — "동료의 카드를 내 업무에 변형"이 1회차에서 정한 공유 운영 원칙의 실행입니다.
3회차 BRIDGE
오늘의 추천 목록이 3회차 워크플로우 실습의 출발점
3회차에서는 '도구 한 개'가 아니라 메타 프롬프트와 워크플로우 오케스트레이션을 다룹니다. 오늘의 카드 10장이 워크플로우의 구성 요소가 됩니다.
실습 · 3회차 전 제출
① 추천 도구 목록(1줄 설명·사용처·강점·제한), ② 빠른 파악 체크리스트 핵심 항목, ③ Ollama 구동 스크린샷 1장. 이 세 가지가 준비되어야 3회차 첫 시간에 바로 워크플로우 실습으로 들어갈 수 있습니다.
