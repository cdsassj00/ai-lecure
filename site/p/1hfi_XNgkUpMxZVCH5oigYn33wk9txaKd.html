초기의 생성형 AI 교육은 좋은 질문을 만드는 데 집중했습니다. 역할을 정하고, 배경을 적고, 원하는 결과 형식을 설명했습니다. 이 방법은 여전히 대화를 분명하게 만드는 데 도움이 됩니다. 그러나 지금의 AI가 수행하는 일을 설명하기에는 부족합니다.

오늘날 AI 서비스는 웹을 검색하고, 파일을 읽고, 코드를 실행하고, 표를 계산하고, 문서를 저장할 수 있습니다. 사용자가 보는 결과는 LLM의 문장 생성만으로 만들어지지 않습니다. 여러 컴퓨터 도구와 권한 체계가 함께 움직인 결과입니다.

중요한 질문은 “무슨 문장으로 시킬까?”에서
“어떤 행동을 어디까지 맡길까?”로 이동합니다.

초보자에게도 이 구분이 필요합니다. 그래야 AI의 말과 실제 실행을 혼동하지 않고, 필요한 도구와 사람의 승인 지점을 정할 수 있습니다.

LANGUAGE MODEL

LLM은 글을 읽고 쓰는
언어모델이다

대규모 언어 모델(LLM)은 입력된 글과 이미지의 패턴을 처리해 다음에 이어질 출력을 생성합니다.

1LLM은 컴퓨터 자체가 아닙니다. 컴퓨터 안에서 실행되는 하나의 모델입니다.

회의 내용을 주면 요약문을 씁니다. 표를 주면 항목의 의미를 분류합니다. 보고서 초안을 요청하면 자연스러운 문장을 만듭니다. 이 능력은 방대한 언어 자료에서 학습한 패턴을 바탕으로 합니다.

LLM은 사용자의 문장을 채점해 정답 창고에서 하나를 꺼내지 않습니다. 지금 입력된 내용에 이어질 출력 후보를 계산해 문장, 코드, 표의 형태로 만들어 냅니다.

LLM의 핵심 능력은
읽기 · 쓰기 · 변환 · 다음 행동 제안입니다.

이 능력만으로 파일을 열거나 메일을 보내지는 못합니다. 실제 행동을 이해하려면 모델과 모델을 둘러싼 실행 환경을 분리해서 봐야 합니다.

구분 연습
“출장비 합계는 1,230,000원입니다”라는 문장을 쓰는 것은 LLM이 할 수 있습니다. 영수증 127장의 금액을 빠짐없이 읽고 합계를 검증하는 일은 문서 인식과 계산 도구가 필요합니다.

LLM이 계산 문제를 문장으로 풀 수 있어도, 중요한 수치는 전용 계산 도구로 다시 확인하는 것이 안전합니다.

‘같은 모델’인데 결과가 다른 이유

용어: 모델과 도구를 연결하고 실행 순서를 관리하는 프로그램 환경을 하네스(harness)라고 부르기도 합니다.

말을 잘하는 것과
사실인 것은 다르다

LLM의 문장은 자연스러울 수 있지만, 자연스러움이 정확성·최신성·권한을 보장하지는 않습니다.

사실 오류

입력에 없는 정보를 그럴듯하게 채울 수 있습니다. 중요한 주장에는 원문, 공식 자료, 계산 근거가 필요합니다.

현재 상태의 부재

검색이나 업무 시스템이 연결되지 않으면 오늘의 일정, 재고, 규정 변경을 직접 확인할 수 없습니다.

행동 권한의 부재

메일 문장을 만드는 것과 메일을 실제 발송하는 것은 다른 일입니다. 발송에는 계정 연결과 권한이 필요합니다.

목표의 부재

모델이 조직의 진짜 목적을 스스로 정하지 않습니다. 사람은 업무 목적, 우선순위, 중단 조건을 제공해야 합니다.

좋은 AI 활용자는 모든 답을 믿는 사람이 아니라,
말·근거·행동을 구분하는 사람입니다.

AGENT SYSTEM

도구가 연결되면
에이전트가 된다

에이전트는 LLM에 여러 컴퓨터 도구를 연결하고, 실행 결과를 다시 읽게 하며, 목표가 끝날 때까지 행동을 이어 가는 시스템입니다.

언어모델 + 실행 환경 + 컴퓨터 도구
+ 자료 + 권한 + 사람의 검토
= 에이전트

에이전트의 중심에는 LLM이 있습니다. LLM은 현재 상태를 읽고 다음 행동을 제안합니다. 실행 환경은 제안된 행동이 허용되어 있는지 확인한 뒤 도구를 호출합니다. 도구 결과는 다시 현재 상태에 추가됩니다.

이 과정이 반복되면 AI는 단순한 답변을 넘어 파일을 찾고, 데이터를 계산하고, 결과 문서를 만들 수 있습니다. 다만 에이전트가 사람처럼 자유롭게 움직인다는 뜻은 아닙니다. 연결된 도구와 허용된 권한 안에서만 행동합니다.

!에이전트의 능력은 LLM의 크기만이 아니라 연결된 도구와 권한으로 결정됩니다.

도구는 AI가 외부 세계의 정보를 읽거나 상태를 바꾸기 위해 호출하는 기능입니다.

도구읽는 행동바꾸는 행동주의점

코드·데이터CSV, 엑셀, 데이터베이스 조회계산, 변환, 그래프 생성수식·행 수·결측 검증
업무 서비스메일, 일정, 고객 정보 조회발송, 등록, 상태 변경계정 권한, 외부 전달
운영체제프로그램과 파일 상태 확인앱 실행, 파일 이동삭제·덮어쓰기 방지

스킬은 도구가 아니다

도구가 실제 실행 기능이라면, 스킬은 특정 업무에서 도구를 어떤 순서와 기준으로 써야 하는지 적은 작업 지침입니다. 예를 들어 ‘보고서 작성 스킬’에는 원문 확인, 표 검증, 페이지 구성, PDF 품질 점검 절차가 들어갈 수 있습니다.

핵심 구분
LLM은 다음 행동을 제안합니다. 도구는 행동을 실행합니다. 스킬은 실행 방법을 안내합니다. 에이전트 환경은 이들을 연결하고 반복을 관리합니다.

챗봇, 워크플로,
에이전트는 다르다

구분동작 방식적합한 일예외 대응
챗봇질문을 받고 답변을 생성설명, 요약, 초안, 상담사람이 다음 질문
워크플로미리 정한 순서대로 실행정형 반복 업무, 승인 절차규칙으로 분기
에이전트중간 결과를 보고 다음 행동 선택자료 상태와 경로가 달라지는 업무계획을 수정하고 도구 재사용

모든 일을 에이전트로 만들 필요는 없습니다.

절차가 매번 같고 오류 비용이 큰 업무는 고정된 워크플로가 더 안정적입니다. 자료 위치가 달라지고 예상하지 못한 예외가 자주 생기는 업무는 에이전트의 판단이 도움이 됩니다.

둘을 함께 쓰는 방식

실무에서는 워크플로 안에 에이전트를 넣거나, 에이전트가 승인된 워크플로를 호출합니다. 예를 들어 문의 내용을 에이전트가 분류하되, 환불 처리는 정해진 승인 워크플로를 따르게 할 수 있습니다.

선택 기준: 정답 경로가 고정되면 워크플로, 경로를 중간에 선택해야 하면 에이전트, 최종 판단이 중요하면 사람의 승인을 둡니다.

  3. 수치 계산　데이터 도구가 월별 매출과 증감률을 계산합니다.
  4. 이상 확인　에이전트가 빈 셀과 급격한 변화를 발견하면 계산 방법을 바꾸거나 사람에게 묻습니다.
  5. 초안 작성　LLM이 검증된 수치와 회의 내용을 연결해 보고서 문장을 작성합니다.
  6. 파일 생성　문서 도구가 A4 보고서와 그래프를 만들고 PDF로 저장합니다.
  7. 품질 점검　페이지 잘림, 수치 일치, 누락된 출처를 확인합니다.
  8. 사람의 승인　담당자가 해석과 대외비 포함 여부를 확인해 사용을 결정합니다.
